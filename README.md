# Oracle Quiz Platform

Платформа онлайн-тестирования, где ключевая логика реализована в Oracle (SQL/PLSQL), а Python (Tkinter) используется как GUI-клиент.

## Папка для переноса

Готовый переносимый комплект собирается в `OracleQuizPlatform_Release` командой
`powershell -ExecutionPolicy Bypass -File .\build\prepare_release.ps1 -Python .\.venv\Scripts\python.exe`.
В нём один README, EXE, исходники Python без тестов и только SQL-зависимости установки
и обновления. Проверка компиляции вынесена из tests в `sql/check_installation.sql`;
тестовые сценарии не входят и во встроенный SQL-комплект EXE. В комплект включены
`rebuild.ps1`, `build/build_exe.ps1` и зависимости для пересборки на другом Windows-ПК.
Команда из релизной папки: `powershell -ExecutionPolicy Bypass -File .\rebuild.ps1`
(нужен Python 3.12 x64 с pip и Tcl/Tk). Новая сборка проверяется перед заменой EXE;
промежуточные файлы остаются в `%TEMP%`, а не в релизе.
Docker, кэши и настройки компьютера не копируются. Папка релиза исключена из Git;
скрипт и шаблон инструкции сохраняются в репозитории. Существующая релизная папка
автоматически не удаляется и не перезаписывается: перенесите её или задайте новое
имя через `-ReleaseName OracleQuizPlatform_Release_2`.

Для переноса содержимого релиза в учебный GitLab без установленного Git предусмотрены
`publish_gitlab.ps1` и `upload_gitlab.cmd`. CMD-файл запускается двойным щелчком и
оставляет окно открытым при ошибке. Загружаются файлы в корень указанного проекта,
включая замену README, без удаления посторонних файлов. Токен с областью `api`
вводится скрыто; HTTP требует осознанного разрешения. Порядок работы описан в
единственном README релизной папки. Проверки API выполняются на локальном имитаторе;
доступ и ограничения конкретного учебного GitLab проверяются при реальной загрузке.

## Ключевая идея

- Oracle отвечает за бизнес-логику: права, валидацию, таймеры, оценивание, публикацию, удаление, ограничения целостности.
- Python отображает формы, проверяет ввод и вызывает API Oracle. Оценивание, ограничения и изменения данных выполняются в БД; SQL-запросы из `database.py` тоже исполняются сервером Oracle.
- Представления не используются: семь процедур `pkg_reports` возвращают отчёты через `SYS_REFCURSOR`. Право `CREATE VIEW` не требуется.

## Основные возможности

- Регистрация и вход по логину/паролю.
- Роли: `USER`, `AUTHOR`, `ADMIN`.
- Управление тематиками, категориями, тестами, вопросами, вариантами ответов.
- Типы вопросов: `SINGLE_CHOICE`, `MULTIPLE_CHOICE`, `TEXT`, `NUMBER`, `BOOLEAN`, `ORDERING`.
- Таймер: на весь тест (`QUIZ`) или на каждый вопрос (`QUESTION`).
- Автопереход на следующий вопрос по таймауту в режиме `QUESTION`.
- Публикация и возврат теста в черновик.
- Переключение черновика между публичным доступом и доступом по приглашению без удаления результатов.
- Подключение Oracle через отдельные поля сервера, порта и SID/имени службы; ручная строка DSN остаётся дополнительным режимом.
- Ограничение числа попыток на пользователя (`attempt_limit`).
- Настройка показа правильных ответов и пояснений (`show_feedback`).
- Сравнение результата попытки со средним по завершённым и прерванным попыткам других участников этого теста: средний процент, разница в процентных пунктах, размер выборки. Расчёт выполняется в Oracle.
- Удаление тестов/вопросов с пересчетом связанных данных.
- Админ-функции: создание авторов, роли, смена пароля пользователя, отключение/включение аккаунта, удаление пользователя, сброс прогресса.

## Правильные варианты вопросов

В редакторе вопросов «Один вариант» (`SINGLE_CHOICE`) использует выпадающий список:
можно выбрать только один правильный ответ. Для «Нескольких вариантов» остаётся
ввод номеров через запятую, но нужно минимум два разных правильных ответа.
Один номер и повторы вроде `1,1` не подходят; неизвестные номера и некорректный ввод отклоняются.
Нужно минимум два варианта. Если выбранная строка изменена или удалена, выберите
правильный ответ заново. При редактировании старого одиночного вопроса с несколькими
правильными ответами редактор не угадывает ответ: автор должен явно выбрать один.

Oracle `pkg_admin.add_option` запрещает второй правильный вариант у `SINGLE_CHOICE`
и `BOOLEAN`. Перед фиксацией создания/редактирования клиент вызывает
`pkg_admin.validate_question`: одиночный тип требует ровно один правильный вариант,
множественный минимум два. Те же правила проверяются при публикации теста.
Ошибка сохранения откатывает весь вопрос, не оставляя частичных изменений.
Незавершённые вопросы допустимы в черновике через прямой PL/SQL, но не публикуются.
При прохождении можно отметить один вариант, но неполный правильный набор даёт
0 баллов; только полное совпадение с правильным набором даёт баллы за вопрос.
Старые вопросы с одним правильным ответом автоматически не переписываются:
автор должен исправить их в черновике либо выбрать тип «Один вариант».

Для существующей актуальной базы закройте клиент, сделайте резервную копию и выполните
в SQL Developer через F5 `sql/upgrade_question_options.sql` из новой полной папки `sql`,
затем замените EXE. Скрипт обновляет спецификацию и тело `pkg_admin` и проверяет компиляцию;
пароли, попытки и существующие ответы не меняются. Предыдущее обновление без views
также включает актуальный `pkg_admin`. При новой установке исправление входит в `install.sql`.

## Управление пользователями

Администратор открывает «Студия тестов» → «Команда» и выбирает пользователя
в таблице. Под таблицей закреплены кнопки смены роли, пароля, включения,
отключения и удаления аккаунта. При уменьшении окна кнопки переносятся
на несколько строк; таблица прокручивается отдельно. Если при большом масштабе
не помещается весь раздел, доступна прокрутка самой вкладки. Без выбранного пользователя
действия недоступны.

«Добавить автора» открывает отдельную форму имени, логина и временного пароля.
«Сменить пароль» открывает форму для выбранного аккаунта: введите новый пароль
длиной от шести символов и нажмите «Сохранить пароль» или Enter. Escape и «Отмена»
закрывают форму без сохранения. Ошибки отображаются внутри формы.
Создание автора не переключает администратора с вкладки «Команда».

Для обновления этой разметки достаточно заменить `dist/OracleQuizPlatform.exe`.
Повторно запускать установку Oracle или удалять данные не нужно.

## Отображение на небольшом экране

- Длинные страницы подключения, входа, регистрации, прохождения и результатов
  прокручиваются; содержимое не сжимается ниже требуемого размера.
- Все вкладки студии имеют прокрутку. Список «Раздел студии» позволяет открыть
  любой раздел, даже если названия вкладок не помещаются по ширине.
- На узком экране панели материалов, редактора вопросов и прогресса размещаются
  друг под другом. Группы кнопок переносятся на следующую строку.
- Колесо мыши прокручивает область под указателем; Shift + колесо используется
  для горизонтальной прокрутки. Таблицы имеют собственные полосы прокрутки.
- При переходе Tab к полю или кнопке страница автоматически показывает этот элемент.

Компоненты и ограничения описаны в [документации разметки](docs/09_responsive_layout.md).
При переносе исходников включайте весь каталог `app/quiz_client`, в том числе `layout.py`.

## Начальные данные

После новой установки создаются три активных аккаунта приложения:

| Логин | Пароль | Роль |
| --- | --- | --- |
| `admin` | `Admin123!` | Администратор |
| `author` | `Author123!` | Автор |
| `student` | `Student123!` | Участник |

Это демонстрационные пароли: перед использованием вне защиты проекта измените их.
Они не являются паролями Oracle-схемы. Пароль существующего администратора при
обычном обновлении не меняется.

Сразу доступны три опубликованных публичных теста:

| Тест | Автор | Время на весь тест | Вопросов | Баллов |
| --- | --- | --- | --- | --- |
| Oracle: основы серверной логики | `admin` | 20 минут | 6 | 8 |
| Математика: базовые знания | `author` | 15 минут | 6 | 8 |
| Русский язык: базовые знания | `author` | 10 минут | 6 | 8 |

В каждом тесте представлены все шесть типов вопросов; пояснения включены,
число попыток не ограничено. У `author` и `student` сохранено по 12 завершённых
демонстрационных прохождений: по четыре каждого теста, всего 24 сессии и 144 ответа.
Охвачены все шесть типов вопросов, есть результаты 0%, 37,5%, 62,5% и 100%.
Вопросы математики и русского языка привязаны к собственным тематикам и категориям.
Все данные создаются в Oracle установочными скриптами `sql/07_seed`, не Python-клиентом.

## Подключение к БД

Для установки с нуля теперь не нужен SQL Developer: заполните данные схемы на экране
подключения и нажмите **«Установить базу приложения (install.sql)»**. Подтвердите
предупреждение и введите имя схемы. Дождитесь окончания, закройте окно установки и
нажмите «Подключиться». В EXE SQL-файлы уже встроены; Oracle и пользователь схемы
должны существовать заранее. [Подробная инструкция](docs/11_installation_from_app.md).

**Кнопка полностью переустанавливает проект: старые пользователи приложения, тесты
и результаты удаляются. Для обычного входа и обновления её не используйте.**

В окне «Шаг 1. Подключение Oracle» заполните поля:

| Поле | Локальный Docker | Пример учебного сервера |
| --- | --- | --- |
| Сервер | `localhost` | `10.22.10.64` |
| Порт | `1521` | `1521` |
| Тип подключения | Имя службы (Service name) | SID |
| Имя службы / SID | `FREEPDB1` | `orcl` |
| Пользователь схемы | `quiz_app` | `KA2105_01` |
| Пароль схемы | `P@ssw0rd` | Ваш пароль схемы на сервере |

Значения удалённого сервера сверяйте с рабочим подключением SQL Developer.
SID и Service name не взаимозаменяемы: выберите тот же тип, что в SQL Developer.
После нажатия «Подключиться» откроется отдельный вход по логину пользователя приложения.
Адрес и имя схемы запоминаются в `%APPDATA%/OracleQuizPlatform/connection.json`, пароль не записывается.
Старые настройки DSN автоматически разбираются по полям. Для сложного дескриптора или TNS-алиаса
используйте флажок «Ввести готовую строку подключения (дополнительно)»: исходная строка сохраняется.

Если Docker-том создан со старым паролем схемы, один раз выполните смену пароля,
затем обновите модули. Данные сохраняются:

```powershell
powershell -ExecutionPolicy Bypass -File .\docker\change_schema_password.ps1
powershell -ExecutionPolicy Bypass -File .\docker\upgrade.ps1
```

Скрипт меняет только пароль Oracle-схемы `quiz_app`. Пароли пользователей приложения
хранятся отдельно в `app_users`; существующий пароль администратора не сбрасывается.
`admin / Admin123!` выше относится к новой установке. Для существующей базы используйте
пароль администратора, который установили ранее.

## Изменение доступа к тесту

В «Студия тестов → Публикация» выберите свой тест. Опубликованный тест сначала
скройте в черновик. В поле «Доступ к тесту» выберите «Публичный» либо «По приглашению»
и нажмите «Сохранить настройки» или сразу «Опубликовать выбранный тест».
Публичный тест доступен всем активным участникам приложения, закрытый только приглашённым,
его автору и администратору. Черновики в каталоге прохождения не показываются.

Доступ, лимит попыток и показ пояснений сохраняются вместе: ошибка любого параметра
откатывает всю настройку. Приглашения, ответы, результаты и использованные попытки
не удаляются при переключении. Старые приглашения снова действуют после возврата
к закрытому режиму.

Для закрытого теста ниже настроек показан список доступа: логин, имя, роль,
основание доступа, активность аккаунта и дата приглашения. Выдача и отзыв относятся
именно к тесту, выбранному в верхней таблице. Выберите пользователя в списке и нажмите
«Отозвать доступ», затем подтвердите действие. Список обновится сразу; для изменений
другого автора/администратора есть «Обновить доступ».

Отзыв удаляет только приглашение и запрещает новые попытки. Результаты и начатые
попытки сохраняются; повторная выдача не сбрасывает использованный лимит прохождений.
Автор и администраторы имеют доступ по роли: такие строки видны, но отозвать их этой
кнопкой нельзя. Отключённые аккаунты отмечены отдельно и не могут входить.

Для обновления списка и отзыва в уже установленной базе перенесите всю новую папку
`sql`, выполните **`sql/upgrade_quiz_invitations.sql`** через F5 в своей схеме (UTF-8),
затем замените EXE. Данные и пароли сохраняются, CREATE VIEW не требуется.
**Кнопку установки базы и `install.sql` для такого обновления не используйте.**

Для уже установленной актуальной базы закройте приложение, перенесите всю обновлённую
папку `sql` и выполните **`sql/upgrade_quiz_access.sql`** в своей схеме через F5 в SQL Developer
(кодировка UTF-8). Скрипт обновляет спецификацию и тело `pkg_admin`, не меняет данные и пароли,
не требует SYS или CREATE VIEW. Затем замените EXE. Для старой версии с представлениями
сначала используйте полное безопасное обновление `sql/upgrade_no_views.sql`.
**Не запускайте `install.sql` поверх рабочих данных: он удаляет их.**

## Подбор вопросов по параметрам

В студии откройте вкладку **Подбор**, выберите черновик и режим «Случайные N по категории и сложности».
Укажите категорию, сложность и количество, нажмите **Сохранить подбор**, затем публикуйте тест.
Источник: только вопросы выбранного теста. Oracle выбирает ровно N вопросов без повторов
при каждой новой попытке; набор и порядок сохраняются в `attempt_questions`.
По умолчанию используются все вопросы по порядку. [Подробное описание](docs/07_question_selection.md).

## Обновление установленной схемы

Закройте клиент перед обновлением и сделайте резервную копию схемы.
В Docker выполните `powershell -ExecutionPolicy Bypass -File .\docker\upgrade.ps1`.
На учебном сервере откройте **файл** `sql/upgrade_no_views.sql` в SQL Developer,
выберите подключение своего пользователя БД и запустите F5. Папка `sql` должна быть перенесена целиком:
скрипт использует относительные `@@`-подключения. Он рассчитан на актуальную установленную версию проекта
(с режимами таймера и лимитом попыток), добавляет недостающие поля подбора и пересоздаёт пакеты,
включая `pkg_reports`. SYS, создание пользователя и `CREATE VIEW` не нужны.
Затем запустите `sql/tests/question_selection_smoke_test.sql` и `sql/tests/comparison_smoke_test.sql`
через F5 и замените EXE. Пароли, тесты и результаты не сбрасываются.
`sql/install.sql` повторно не запускайте: это установка с удалением данных приложения.

Новый EXE требует `pkg_reports`: сначала обновите базу, затем замените клиент.
Для новой схемы по-прежнему используется `sql/install.sql`. Достаточны права
`CREATE SESSION`, `CREATE TABLE`, `CREATE SEQUENCE`, `CREATE PROCEDURE`, `CREATE TRIGGER`
и квота на табличное пространство. Проверено с квотой 300 МБ.
Подробные шаги SQL Developer и проверочные запросы:
[Развёртывание без CREATE VIEW](docs/10_deployment_without_views.md).

## Новые демонстрационные данные в существующей схеме

Замена EXE или обычный `docker/upgrade.ps1` не добавляют seed-данные повторно.
Для новой установки перенесите папку `sql` целиком: `install.sql` включает
`07_seed/03_subjects_and_users.sql` и `07_seed/04_demo_attempts.sql`. В SQL Developer установите кодировку UTF-8,
откройте сам файл `sql/install.sql` и выполняйте через F5 только в новой схеме
или при намеренной переустановке с потерей прежних данных.
В SQL*Plus запускайте `@install.sql` из каталога `sql`, чтобы находились вложенные скрипты.

Если нужно добавить только два новых теста и аккаунта в уже установленную базу,
сначала сделайте резервную копию и убедитесь, что логины `author`, `student`
и тематики «Математика», «Русский язык» ещё не заняты. Подключитесь владельцем схемы,
откройте `sql/07_seed/03_subjects_and_users.sql` в UTF-8 и выполните F5, затем `COMMIT;`
только после успешного завершения. Требуется действующий администратор с логином `admin`.
Скрипт рассчитан на однократный запуск, не заменяет существующие записи и не меняет
пароль администратора. При ошибке выполните `ROLLBACK;` и разберите причину,
не запускайте вместо него полную установку.

Если аккаунты и три исходных теста уже есть, для добавления сохранённых сессий
достаточно выполнить в SQL Developer через F5 файл `sql/07_seed/04_demo_attempts.sql`
в кодировке UTF-8, затем `COMMIT;` после успешного завершения. Он доводит число
завершённых попыток каждого из двух аккаунтов по каждому начальному тесту до четырёх,
не удаляя существующие результаты. Повторный запуск при достигнутом количестве
не добавляет дубликаты. Аккаунты должны быть активны, а исходные тесты опубликованы
и не изменены. При ошибке новые сессии этого запуска откатываются.
Это только демонстрационные результаты для сдачи: они входят в отчёты и средние,
поэтому скрипт не следует запускать в схеме с реальными оценками учащихся.

## Проверка условий допуска к защите

Пользователь приложения хранится в `app_users`, игровая сессия соответствует попытке
в `attempts`; ответы находятся в `user_answers` и `answer_choices`.
После новой установки доступны два аккаунта помимо администратора и по 12 завершённых
сессий у каждого. Войдите как `author` или `student` и откройте «Мои результаты».

В SQL Developer выполните:

```sql
SELECT u.login, u.role_code, COUNT(a.attempt_id) AS completed_sessions
FROM app_users u
LEFT JOIN attempts a ON a.user_id = u.user_id AND a.status = 'FINISHED'
WHERE u.is_active = 1
GROUP BY u.login, u.role_code
ORDER BY u.login;

SELECT u.login, q.title, COUNT(*) AS completed_sessions
FROM attempts a
JOIN app_users u ON u.user_id = a.user_id
JOIN quizzes q ON q.quiz_id = a.quiz_id
WHERE a.status = 'FINISHED'
GROUP BY u.login, q.title
ORDER BY u.login, q.title;

SELECT u.login, q.type_code, COUNT(*) AS saved_answers
FROM user_answers ua
JOIN attempts a ON a.attempt_id = ua.attempt_id
JOIN app_users u ON u.user_id = a.user_id
JOIN questions q ON q.question_id = ua.question_id
WHERE a.status = 'FINISHED'
GROUP BY u.login, q.type_code
ORDER BY u.login, q.type_code;
```

Ожидается 12 сессий у `author` и 12 у `student`; у каждого по четыре сессии каждого
из трёх тестов и по 12 ответов каждого из шести типов. `admin` не имеет начальных сессий.
Это аккаунты приложения, не отдельные Oracle-схемы.

Описания логики сохранены в `docs`: комментарии и описательные docstring удалены
из исходного кода проекта, но SQL-запросы, тексты интерфейса и пояснения к вопросам сохранены.

## Сборка EXE

На новом компьютере создайте отдельное окружение из установленного Python
(проверено на Python 3.12 x64). Команды выполняются из корня проекта:

```powershell
python -m venv .venv
powershell -ExecutionPolicy Bypass -File .\build\build_exe.ps1 -Python .\.venv\Scripts\python.exe
```

Если `.venv` уже создана на этом компьютере, первая команда не нужна.
Не переносите `.venv` с другой машины. Скрипт устанавливает зависимости в выбранный
Python, проверяет их импорт, собирает EXE и проверяет зависимости внутри него.
Успешное окончание: `EXE verified`. При ошибке не используйте оставшийся старый EXE.

Артефакт: `dist\OracleQuizPlatform.exe`. Отчёты: `build\pyinstaller\source-check-*.json`
и `build\pyinstaller\exe-check-*.json`.

Проверка нового EXE на другом компьютере без подключения к Oracle:

```powershell
$report = Join-Path $PWD ('dependency-check-' + [guid]::NewGuid().ToString('N') + '.json')
$process = Start-Process -FilePath .\dist\OracleQuizPlatform.exe -ArgumentList @('--self-check', ('"{0}"' -f $report)) -WindowStyle Hidden -Wait -PassThru
$process.ExitCode
Get-Content -LiteralPath $report -Raw -Encoding UTF8
```

`0` означает успешную проверку зависимостей, но не доступность БД.
Режим `--connection-check DSN SCHEMA_USER SCHEMA_PASSWORD LOGIN PASSWORD` также сохранён;
он действительно подключается и выполняет вход (включая серверные действия `pr_login`).
Не публикуйте команды с действующими паролями. Для оконного EXE ожидайте завершения
через `Start-Process -Wait -PassThru` и читайте `ExitCode`, а не старый `$LASTEXITCODE`.

Подробные шаги для удалённого Windows, ошибки импорта и состав переносимых файлов:
[Сборка и диагностика зависимостей](docs/08_build_and_dependencies.md).
