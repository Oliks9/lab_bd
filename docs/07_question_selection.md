# Подбор N вопросов из категории X сложности Y

Дата: 12.09.2026.

## Как пользоваться

1. Войдите как автор или администратор, откройте студию и создайте черновик.
2. Во вкладке «Вопросы» добавьте вопросы именно в этот тест, назначьте им категории и сложность.
3. Откройте «Подбор» и выберите тест. Для опубликованного теста сначала выполните «Скрыть в черновик» во вкладке публикации.
4. Выберите «Случайные N по категории и сложности», категорию, сложность и N (целое 1..1000).
5. Проверьте показанное количество подходящих вопросов. Оно запрашивается из Oracle, а не считается в Python.
6. Нажмите «Сохранить подбор», затем перейдите к публикации. При нехватке вопросов настройки черновика сохраняются, но публикация отклоняется с пояснением, сколько нужно и сколько доступно.
7. Для отключения подбора выберите «Все вопросы по порядку» и сохраните. Тогда используются все вопросы теста в порядке автора.

Например, из 12 вопросов теста 7 относятся к категории «SQL» и сложности «Средняя».
При N=4 каждая новая попытка получит 4 случайных вопроса из этих семи, в случайном порядке.
Вопросы других категорий, сложностей и тестов не попадут в набор. Повторов внутри одной
попытки нет; между разными попытками совпадения допустимы, различие наборов не гарантируется.
При N, равном размеру набора, меняется только порядок.

Параметры подбора применяются только после нажатия «Сохранить подбор».
Переход на вкладку заново загружает сохранённые настройки и новые категории из базы.
Новые тесты по умолчанию используют все вопросы. Старый вручную заданный `question_limit`
без фильтров продолжает выбирать первые N; интерфейс предупреждает, что сохранение режима
«Все» снимет такой старый лимит.

## Что выполняется в Oracle

| Объект | Назначение |
|---|---|
| `quizzes.question_limit` | N для подбора; NULL означает все вопросы без фильтров |
| `quizzes.selection_category_id` | Фильтр категории, FK на `categories` |
| `quizzes.selection_difficulty_code` | Фильтр сложности, FK на `difficulty_levels` |
| `ck_quizzes_selection` | Оба фильтра либо NULL, либо заполнены вместе с целым N от 1 до 1000 |
| `fn_quiz_pool_count(quiz_id, category_id, difficulty_code)` | Число подходящих вопросов; NULL-фильтр не ограничивает выборку |
| `pkg_admin.set_quiz_selection(actor_id, quiz_id, N, category_id, difficulty_code)` | Проверки роли, владельца, черновика, N, категории из тематики теста и сложности; сохранение настроек |
| `pkg_admin.require_selection_pool` | Внутренняя проверка количества при публикации и удалении вопроса опубликованного теста |
| `pkg_testing.start_attempt` | Проверка доступа, лимита попыток, доступности N, случайный отбор SQL-запросом и запись набора |
| `attempt_questions` | Конкретные ID выбранных вопросов и их `display_order` для этой попытки |
| `pkg_reports.catalog` | N, число подходящих вопросов, категория и сложность для каталога |

Для выбора используется `ROW_NUMBER() OVER (ORDER BY DBMS_RANDOM.VALUE, question_id)`
после фильтрации по `quiz_id`, категории и сложности. Строки с номером не больше N
записываются в `attempt_questions` один раз. Повторное чтение попытки не вызывает случайный отбор.
Без фильтров сохраняется прежний порядок `questions.seq_no`.

Изменения автора и начало попытки блокируют одну строку теста через `FOR UPDATE`.
Права и публикация при старте перепроверяются после получения блокировки.
При невозможности набрать N ошибка возникает до вставки `attempts`, поэтому лимит не расходуется.
Пакеты не делают COMMIT; GUI фиксирует успешный вызов сохранения/старта, при ошибке выполняет ROLLBACK.
При прямых вызовах из SQL Developer транзакцией управляет вызывающий код.

Фильтры не требуют новых триггеров: ограничения находятся в FK/CHECK и PL/SQL-пакетах.
Существующий `trg_quizzes_biu` по-прежнему обновляет дату изменения теста.
Python содержит только форму, преобразование ввода и вызовы Oracle, без случайного выбора вопросов.

## Результаты, таймеры и удаление

- В обоих режимах таймера используются только выбранные вопросы. Последний ответ или таймаут последнего вопроса завершает попытку обычным серверным механизмом.
- Максимум баллов и процент считаются по фактическому набору; 100% остаётся достижимым независимо от того, какие вопросы выпали.
- В каталоге показывается N. Сумма баллов до старта неизвестна, потому выводится «По подбору», а не сумма всех вопросов теста.
- Пояснения, история, сравнение со средним и статистика используют существующие механизмы. Разные подборки сравниваются по проценту в рамках того же теста; сложность изменённых версий отдельно не нормализуется.
- Статистика вопроса по-прежнему считает сохранённые ответы на этот вопрос (`user_answers`), а не все попытки теста. Невыбранные вопросы и пропуски без сохранённого ответа не входят в знаменатель `correct_percent`.
- Изменение настроек черновика само по себе не меняет наборы уже созданных попыток. Это фиксация ID и порядка, а не копия текстов вопросов: отдельное версионирование содержимого не добавлялось.
- Удаление вопроса сохраняет прежний пересчёт затронутых попыток. Дополнительно нельзя уменьшить набор опубликованного теста ниже N. Нужно сначала скрыть тест и изменить подбор. Активные попытки, как и раньше, запрещают удаление вопроса.
- Категорию, указанную в подборе хотя бы одного теста, нельзя удалить, даже если она пустая. Сначала смените или отключите соответствующие настройки.

## Обновление существующей базы

Не запускайте `sql/install.sql` на базе с нужными данными: он удаляет объекты и результаты.
Перед DDL сделайте резервную копию и закройте приложение: DDL Oracle фиксируется автоматически,
поэтому общим ROLLBACK миграцию отменить нельзя.

Для Docker из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\docker\upgrade.ps1
powershell -ExecutionPolicy Bypass -File .\docker\check.ps1
```

Для установленной схемы учебного сервера:

1. Перенесите всю папку `sql` без изменения вложенности.
2. В SQL Developer подключитесь владельцем своей схемы, не SYS и не пользователем приложения `admin`.
3. Откройте файл `sql/upgrade_question_selection.sql`, выберите нужное подключение и выполните F5. `@@` работает относительно сохранённого скрипта, поэтому не копируйте только текст в несохранённый worksheet.
4. Проверьте вывод `check_invalid_objects.sql`: ошибок компиляции быть не должно.
5. Откройте и выполните F5 `sql/tests/question_selection_smoke_test.sql`. Ожидаемое сообщение: `Question selection smoke test passed.` Данные проверок откатываются; существующие тесты не удаляются.
6. Замените клиент новым `dist/OracleQuizPlatform.exe`. Новому клиенту нужны новые столбцы, функция и пакеты; одной замены EXE недостаточно.

Скрипт точечного обновления рассчитан на предыдущую актуальную версию проекта.
Последовательность внутри: миграция `20260912_question_selection.sql`, функция количества,
`pkg_testing` (spec/body), `pr_login`, `pkg_admin` и `pkg_reports` (spec/body), проверка компиляции.
Представления больше не создаются; `CREATE VIEW` не нужен. Обёртка `sql/upgrade_no_views.sql`
выполняет это же обновление. Подробнее: `10_deployment_without_views.md`.
Миграция повторно запускаемая, не меняет пользователей, пароли, старые лимиты и попытки.
Дополнительных административных прав сверх прав владельца на объекты проекта не требуется;
`DBMS_RANDOM` должен быть доступен схеме (при ограничении DBA должен предоставить EXECUTE).

## Проверки

SQL-сценарий покрывает изоляцию тестов/категорий/сложностей, некорректное N, чужого автора,
обычного участника, доступ администратора, недостаточный набор на публикации и старте,
точный размер и уникальность набора, последовательный `display_order`, неизменность набора,
баллы 100% по выбранным вопросам, таймер вопроса, возврат к полному списку, старый лимит,
защиту удаления вопроса и категории. Все fixtures откатываются к savepoint.

GUI-тесты не требуют БД и используют тестовый gateway:

```powershell
$env:PYTHONPATH = "$PWD\app"
python -m unittest discover -s app/tests -v
```

Нужен Python с работающим Tk. В окружении проекта со специальным bundled-runtime
используйте `build/tcl_runtime/bin` в PYTHONPATH и соответствующие `TCL_LIBRARY`, `TK_LIBRARY`,
как в `build/build_exe.ps1`. Проверяются сохранение, отключение подбора, ошибки ввода,
запрет изменения опубликованного теста, обновление категорий, пустой список и размер 1060x700.
`test_gateway_transactions.py` дополнительно проверяет передачу параметров и освобождение
блокировок через ROLLBACK после неуспешных вызовов изменения теста.
