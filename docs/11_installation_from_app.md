# Установка из приложения

Актуально на 21.09.2026.

## Назначение

Кнопка «Установить базу приложения (install.sql)» на первом экране выполняет
существующий `sql/install.sql`, включая вложенные `@@`-файлы, через python-oracledb.
SQL Developer, SQL*Plus и Oracle Client на компьютере пользователя не нужны.
Бизнес-логика, создание данных и проверка объектов выполняются в Oracle, а не в Python.

Это не мастер безопасного обновления. Скрипт сначала вызывает `00_uninstall.sql`:
удаляет объекты проекта, аккаунты приложения, тесты и результаты, после чего создаёт
начальные данные. Сама учётная запись схемы Oracle и её пароль не пересоздаются.
Не используйте рабочую схему без резервной копии и согласованной переустановки.

## Требования

- Oracle уже запущена и доступна с компьютера пользователя.
- Есть отдельный обычный пользователь схемы и его пароль; не SYS/SYSTEM/PDBADMIN.
- Права: CREATE SESSION, CREATE TABLE, CREATE SEQUENCE, CREATE PROCEDURE, CREATE TRIGGER.
- Есть свободная квота в табличном пространстве по умолчанию; для проекта выделялась квота 300 МБ.
- CREATE VIEW не нужен. Создание пользователя БД и выдача прав остаются обязанностью администратора Oracle.
- Остальные клиенты проекта отключены от этой схемы на время установки.

## Порядок действий

1. Запустите новый `dist/OracleQuizPlatform.exe`.
2. Введите сервер, порт, SID/имя службы, имя схемы и пароль схемы.
3. Нажмите «Установить базу приложения (install.sql)», а не обычное подключение.
4. Прочитайте предупреждение об удалении данных. По умолчанию выбран отказ.
5. После согласия введите имя схемы ещё раз. Отмена или несовпадение ничего не запускают.
6. Дождитесь сообщения об успешной установке. Ход и вывод Oracle показаны в окне.
7. Закройте окно установки, нажмите «Подключиться», затем войдите в приложение.

После чистой установки: `admin / Admin123!`, `author / Author123!`, `student / Student123!`.
Создаются три теста и 24 завершённые демонстрационные попытки. Это именно начальные
пароли: переустановка удаляет ранее изменённые пароли пользователей приложения.

Для каждого следующего запуска используйте только «Подключиться». Если несколько
компьютеров используют одну БД, установка требуется один раз для общей схемы.
Для сохранения существующих данных используйте отдельные `upgrade_*.sql` по инструкции
соответствующего обновления, а не эту кнопку.

## Файлы и исполнение

- `app/quiz_client/installer.py`: заранее читает полный набор файлов UTF-8, разворачивает
  относительные включения, проверяет права/квоту, выполняет команды и читает DBMS_OUTPUT.
- `app/quiz_client/installation_ui.py`: два подтверждения, фоновый поток со своим
  соединением Oracle, очередь обновлений GUI, прогресс и журнал.
- `app/quiz_client/ui.py`: передаёт введённые реквизиты и блокирует обычное подключение
  и штатное закрытие приложения во время выполнения.
- `build/build_exe.ps1`: включает весь каталог `sql` в EXE. Используются скрипты именно
  из этой сборки, не случайная внешняя папка рядом с EXE. Изменили SQL: пересоберите EXE.
- `diagnostics.py`: `--self-check` проверяет наличие и разбор встроенного install.sql.

При запуске из исходников каталог `sql` должен находиться в корне проекта рядом с `app`.
Разбор скриптов рассчитан на формат проекта, а не на произвольный SQL*Plus: обычные SQL
заканчиваются `;`, PL/SQL-блоки и модули отдельной строкой `/`. Поддержаны `@@`, `PROMPT`,
`SET DEFINE OFF`, `SET SERVEROUTPUT ON`, `WHENEVER SQLERROR EXIT SQL.SQLCODE`.
Неподдерживаемые команды SQL*Plus, циклы/выход включений за каталог и отсутствующие файлы
отклоняются до подключения и до удаления объектов. В текущей установке 57 команд БД.

## Ошибки и ограничения

Журнал UTF-8: `%APPDATA%/OracleQuizPlatform/install_logs/install_*.log`.
Текст SQL и реквизиты подключения туда специально не записываются; пароль схемы
маскируется в сообщениях ошибок. Не публикуйте журнал без просмотра: в нём могут
быть имена объектов и диагностическая информация сервера.

Проверка квоты подтверждает только наличие свободного места, не гарантирует достаточный
объём для любого будущего набора данных. При нехватке прав/квоты установка останавливается
до выполнения `00_uninstall.sql`. Во время выполнения ошибка останавливает последующие
команды и указывает имя файла и строку. Уже выполненные CREATE/DROP не откатываются:
Oracle фиксирует DDL, поэтому сбой может оставить частично установленную схему.
Не закрывайте процесс принудительно и не отключайте сеть. После устранения причины
можно повторить установку только если удаление данных этой схемы по-прежнему допустимо.

При успехе кнопка «Закрыть» становится доступна. При ошибке можно закрыть журнал,
исправить реквизиты или права и повторить действие с новым подтверждением.

## Проверка

Автотесты покрывают разбор UTF-8/вложенных файлов и строк с `;`, недостающие файлы,
циклы и выход за каталог, отказ без прав/квоты, остановку при ошибке, подтверждения,
передачу реквизитов, фоновый прогресс, запрет штатного закрытия и маскирование пароля.
В отдельной Oracle Free 23c с пятью правами и квотой 300 МБ установщик выполнил все
57 команд: 3 пользователя, 3 теста, 18 вопросов, 24 попытки, 144 ответа; объекты VALID,
представлений 0, вход администратора успешен. На этой схеме прошли проверка seed-данных
и все 10 SQL smoke-тестов. Рабочая схема не переустанавливалась.

Дополнительно проверена повторная установка через настоящий GUI-поток и очередь,
журнал UTF-8 и маскирование пароля. Финальный EXE прошёл самопроверку зависимостей
и встроенного SQL-комплекта (57 команд), подключение к Oracle и вход с кодом 0.
Временная схема после проверок удалена. Удалённый учебный сервер не использовался.
