# Матрица ролей и прав

Дата актуализации: 12.09.2026

## 1. Роли

- `USER` — проходит тесты, смотрит свои результаты.
- `AUTHOR` — создает и сопровождает собственные тесты.
- `ADMIN` — полный контроль над пользователями и контентом.

## 2. Где проверяются права

- UI скрывает/показывает кнопки, но это только визуальный уровень.
- Финальные проверки всегда выполняются в Oracle, в `pkg_admin`:
  - `require_editor`
  - `require_admin`
  - `require_quiz_owner`
  - `require_quiz_manager`

Это гарантирует, что прямой вызов SQL в обход GUI не обойдет ограничения.

## 4. Точные правила guard-процедур

## 4.1. `require_editor`

- Разрешены роли: `AUTHOR`, `ADMIN`.
- Используется в авторских операциях контента.

## 4.2. `require_admin`

- Разрешена только роль: `ADMIN`.
- Используется в операциях управления ролями/пользователями и удалении тем/категорий.

## 4.3. `require_quiz_owner`

- Доступ для изменения только к тестам в `DRAFT`.
- Тест должен принадлежать текущему автору, либо пользователь `ADMIN`.
- Используется в `add_question`, `update_question`, `add_option`, `publish_quiz`, `set_quiz_feedback`, `set_quiz_attempt_limit`.

## 4.4. `require_quiz_manager`

- Разрешает управление тестом владельцу или `ADMIN`.
- Не требует `DRAFT`, поэтому подходит для операций удаления и возврата из публикации.
- Используется в `delete_question`, `delete_quiz`, `archive_quiz`.

## 5. Защитные ограничения в admin-операциях

- Публикация подбора требует не меньше N подходящих вопросов внутри выбранного теста.
- Удаление вопроса опубликованного теста запрещается, если нарушает это условие; сначала нужно вернуть тест в черновик и изменить подбор.
- Категорию из настроек подбора нельзя удалить, даже если она пока не содержит вопросов.
- Изменение настроек черновика не пересоздаёт ранее сохранённые наборы попыток.

- Нельзя снять `ADMIN` с текущей учетной записи (`set_user_role`).
- Нельзя отключить текущего администратора (`set_user_active`).
- Нельзя отключить учетную запись с ролью `ADMIN` (`set_user_active`).
- Нельзя удалить текущего администратора (`delete_user`).
- Нельзя удалить любую учетную запись с ролью `ADMIN` (`delete_user`).
- Нельзя удалить вопрос, если есть активные `IN_PROGRESS` попытки по тесту (`delete_question`).

## 6. Практический вывод

Сравнение со средними отображается при открытии собственной попытки для всех ролей.
Oracle исключает из среднего все попытки владельца сравниваемого результата.
В карточке нет имен или отдельных ответов других участников: только агрегаты.

При вызове API приложения права и ограничения проверяются Oracle-пакетами.
Авторские списки и статистика читают актуальную роль из `app_users` в SQL-запросе.
`v_attempt_details` маскирует правильный ответ и пояснения при отключенном показе
или незавершенной попытке.

Клиент использует владельца схемы `quiz_app`, поэтому прямой доступ к таблицам
и подмена ID при ручном SQL не защищены моделью ролей приложения. Границы этой
учебной архитектуры описаны в `06_oracle_logic_audit.md`.
