# Сборка EXE и диагностика зависимостей

## 1. Что означает ошибка oracledb

Сообщение старой версии «Модуль oracledb не установлен» означало любой `ImportError`
при импорте драйвера. Оно не позволяло отличить отсутствие самого пакета от отсутствия
его зависимости или ошибки загрузки DLL. По одному такому сообщению точную причину
на удалённом компьютере установить нельзя.

В новой версии `database.py` сохраняет исходный тип и текст ошибки в
`ORACLEDB_IMPORT_ERROR` и показывает их при подключении. Режим `--self-check` записывает
полный traceback и версии среды в JSON. Он работает отдельно от загрузки основного GUI.

Установка `pip install oracledb` после сборки сама по себе не исправляет уже созданный
EXE: он использует упакованную среду Python. Нужно пересобрать файл с зависимостями
и заменить старый EXE. Переустановка схемы, удаление данных и перенос SQL-файлов
не исправляют ошибку импорта Python.

Приложение использует Thin mode, поэтому для этого режима не требуется Oracle Instant
Client. `cryptography` нужна отдельно и явно включена в `requirements.txt`.
Это соответствует [документации python-oracledb](https://python-oracledb.readthedocs.io/en/latest/user_guide/installation.html).

## 2. Какие файлы переносить

Для пересборки нужны:

```text
oracle_quiz_app/
  app/
    quiz_app.py
    quiz_client/
      __init__.py
      config.py
      database.py
      diagnostics.py
      theme.py
      ui.py
    tests/
  build/
    build_exe.ps1
  requirements.txt
```

Переносите `app` целиком, а не только изменённый `quiz_app.py`: новый режим использует
`quiz_client/diagnostics.py`. Для сдачи кода и развёртывания Oracle также сохраняйте
`sql`, `docs` и `README.md`. Для сборки клиента база данных и Docker не нужны.

Не переносите `.venv`, `__pycache__`, `build/pyinstaller` и старый `.spec` ради сборки:
это локальные или генерируемые файлы. `build/tcl_runtime` является обходным решением
для локального bundled Python и не нужен при обычной установке Python с Tcl/Tk.

Для запуска на совместимом Windows достаточно нового `dist/OracleQuizPlatform.exe`
и сетевого доступа к уже установленной схеме Oracle. Python и папка исходников
на компьютере, где только запускают готовый EXE, не нужны.

## 3. Сборка на удалённом Windows

Закройте старый EXE. Откройте PowerShell и перейдите в корень проекта. Ниже путь является
примером: замените его своим. Нужен установленный Python с `pip` и Tcl/Tk; проект
требует Python 3.10 или новее, локальная проверка выполнена на Python 3.12 x64.
Возможность установки конкретных версий зависимостей зависит также от версии Windows.

```powershell
Set-Location 'C:\Projects\oracle_quiz_app'
python --version
python -c "import sys, struct; print(sys.executable); print(struct.calcsize('P') * 8)"
python -m venv .venv
powershell -ExecutionPolicy Bypass -File .\build\build_exe.ps1 -Python .\.venv\Scripts\python.exe
```

Если команда `python` не найдена, но установлен Python Launcher и Python 3.12,
создайте окружение командой `py -3.12 -m venv .venv`. Активировать окружение не требуется:
путь к нужному интерпретатору передаётся явно. Создавайте `.venv` на целевой машине;
не используйте окружение, скопированное с другого компьютера.

Скрипт последовательно:

1. Определяет абсолютный путь выбранного Python и проверяет его версию.
2. Устанавливает `requirements.txt` именно в этот Python и запускает `pip check`.
3. Проверяет драйвер, криптографию и Tkinter в исходном приложении.
4. Вызывает PyInstaller из того же интерпретатора с `--collect-all oracledb`,
   `--collect-all cryptography`, `--hidden-import oracledb` и явным путём к `app`.
5. Запускает готовый EXE с `--self-check` без подключения к Oracle, ожидая не более 60 секунд.
6. Проверяет код завершения, результат отчёта и признак `frozen`, затем пишет `EXE verified`.

Опция `--collect-all` собирает подмодули, данные и бинарные зависимости пакета;
`--hidden-import` добавляет явно указанный импорт. Одних этих флагов недостаточно
для проверки запуска, поэтому выполняется дополнительная диагностика готового EXE.
Описание флагов: [документация PyInstaller](https://pyinstaller.org/en/v6.14.2/usage.html).

При ошибке скрипт завершается исключением. Старый файл в `dist` может остаться,
но это не означает, что новая сборка успешна. Публикуйте только EXE из запуска,
завершившегося сообщением `EXE verified`. При таймауте диагностики или блокировке запуска
проверьте совместимость Windows и журналы защиты; не отключайте защиту вслепую.

## 4. Проверка готового EXE без базы

Эта команда поддерживается новой версией приложения; старый EXE не умеет `--self-check`.
В PowerShell из корня проекта выполните:

```powershell
$report = Join-Path $PWD ('dependency-check-' + [guid]::NewGuid().ToString('N') + '.json')
$process = Start-Process -FilePath .\dist\OracleQuizPlatform.exe -ArgumentList @('--self-check', ('"{0}"' -f $report)) -WindowStyle Hidden -Wait -PassThru
$process.ExitCode
Get-Content -LiteralPath $report -Raw -Encoding UTF8
```

Если EXE лежит непосредственно в текущей папке, замените путь на
`.\OracleQuizPlatform.exe`. Каталог отчёта должен существовать и быть доступен для записи.
Уникальное имя исключает случайное чтение старого успешного отчёта.

Коды завершения:

| Код | Значение |
| --- | --- |
| `0` | Все три проверки прошли, отчёт записан |
| `1` | Одна или несколько проверок не прошли; причина находится в JSON |
| `2` | Неверные аргументы режима или не удалось записать отчёт |

Для оконного EXE используйте `Start-Process -Wait -PassThru` и свойство `ExitCode`:
обычный вызов из PowerShell может не дождаться завершения, и `$LASTEXITCODE`
не является надёжным результатом этого запуска.

Отчёт содержит версию Python, разрядность, Windows, путь запуска, признак `frozen`,
версии и пути пакетов, результаты проверок и traceback ошибок. В нём нет паролей,
DSN, данных тестов и содержимого базы, но присутствуют локальные пути пользователя.

## 5. Что проверяется в diagnostics.py

| Функция | Назначение |
| --- | --- |
| `check_oracledb` | Импортирует драйвер и создаёт `ConnectParams` без подключения; проверяет Thin mode |
| `check_cryptography` | Шифрует и расшифровывает служебную строку через Fernet, проверяя загрузку нативных криптографических компонентов |
| `check_tkinter` | Создаёт скрытый корень Tk и ttk-кнопку, обрабатывает геометрию, получает версии Tcl/Tk и уничтожает окно |
| `collect_runtime_report` | Запускает все три проверки; ошибка одной не мешает получить результаты остальных |
| `run_self_check` | Записывает JSON в UTF-8 и возвращает код завершения; работает и без консольных потоков windowed EXE |

Диагностика не вызывает `oracledb.connect`, `pr_login`, SQL или другие процедуры.
Она не меняет попытки, пользователей и настройки. Успешный результат не проверяет
сетевую доступность Oracle, пароль схемы или валидность пакетов БД: это отдельный
этап проверки приложения после сборки.

## 6. Если на удалённой машине ошибка осталась

Вначале получите JSON нового EXE. При ошибке ещё до сборки проверьте выбранную среду:

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); import oracledb; print(oracledb.__version__, oracledb.__file__); import cryptography; print(cryptography.__version__)"
.\.venv\Scripts\python.exe .\app\quiz_app.py --self-check .\source-dependency-check.json
```

Возможные различия:

- `No module named 'oracledb'`: драйвер отсутствует в проверяемой среде или не вошёл в старую сборку.
- Ошибка с другим именем модуля: отсутствует именно эта зависимость; не нужно выдавать это за отсутствие всего драйвера.
- `DLL load failed`: нужен полный traceback, версия Windows и разрядность Python/EXE; по одной фразе нельзя определить, какая библиотека отсутствует или несовместима.
- Исходники проверку проходят, а EXE нет: смотрите frozen-отчёт и `build/pyinstaller/OracleQuizPlatform/warn-OracleQuizPlatform.txt`.
- Все проверки проходят, но подключение не работает: проверяйте сеть, DSN (SID и service name различаются), пароль схемы и сервер Oracle отдельно.

Передавайте для разбора текст конкретной ошибки и отчёт, а не пароли схемы или
пользователей приложения. На удалённой машине результат необходимо проверить отдельно:
локальная успешная сборка не гарантирует совместимость с любой версией Windows Server.
