# Развёртывание без CREATE VIEW

Актуально на 21.09.2026. Представления проекта заменены пакетом `pkg_reports`.
Подсчёт статистики, сравнение со средним, каталог, история и подготовка пояснений
по-прежнему выполняются в Oracle. Python получает готовые строки через `SYS_REFCURSOR`.

## Что требуется

Обновление от 21.09.2026: если уже установлена версия без представлений и с подбором
вопросов, для смены публичного/закрытого доступа достаточно перенести всю новую папку
`sql`, закрыть приложение и запустить `upgrade_quiz_access.sql` в своей схеме через F5
с кодировкой UTF-8. Затем замените EXE. Скрипт пересоздаёт спецификацию и тело `pkg_admin`,
проверяет валидность и не удаляет данные/пароли. Для более старой схемы используйте
полное безопасное обновление `upgrade_no_views.sql`, описанное ниже. `install.sql`
остаётся только для установки с нуля, поскольку удаляет существующие объекты.

В новом EXE длинный DESCRIPTION вводить не нужно: сервер `10.22.10.64`, порт `1521`,
тип **SID**, имя `orcl`, пользователь схемы `KA2105_01` и её пароль вводятся раздельно.
Это параметры ранее показанного подключения: сверяйте их с рабочим SQL Developer.
Для Docker выберите **Имя службы (Service name)** и `FREEPDB1`. Адрес/имя схемы сохраняются,
пароль нет; логин пользователя приложения вводится уже после подключения к Oracle.

Подключение владельцем своей схемы, например `KA2105_01`, а не логином приложения
`admin`. SQL Developer является клиентом; база Oracle должна быть доступна по сети.
По предоставленным параметрам: сервер `10.22.10.64`, порт `1521`, **SID** `orcl`.
Не переключайте SID на Service name без подтверждения администратора сервера.

Набор системных прав, с которым проверена установка:

```text
CREATE SESSION
CREATE TABLE
CREATE SEQUENCE
CREATE PROCEDURE
CREATE TRIGGER
```

Квота 300 МБ достаточна для текущей демонстрационной базы, но не является лимитом
на любой будущий объём данных. `CREATE VIEW`, `CREATE TYPE`, `DBA` и вход SYS не нужны.
Создание пакета в своей схеме разрешается правом `CREATE PROCEDURE`, что указано
в [документации Oracle CREATE PACKAGE](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/CREATE-PACKAGE.html).
Обычные встроенные пакеты Oracle должны оставаться доступными, в частности
`DBMS_RANDOM`, `DBMS_OUTPUT`. В проверенном окружении дополнительных выдач EXECUTE не потребовалось.

Проверки в SQL Developer:

```sql
SELECT USER AS schema_user FROM dual;

SELECT privilege FROM session_privs ORDER BY privilege;

SELECT tablespace_name, bytes, max_bytes FROM user_ts_quotas;

SELECT default_tablespace FROM user_users;
```

Для квоты 300 МБ `max_bytes = 314572800`, для неограниченной квоты `-1`.
Квота должна относиться к табличному пространству, где создаются таблицы.
`USER_*` и `SESSION_PRIVS` являются системными объектами Oracle: их чтение
не требует права создавать собственные представления.

## Что перенести

- Всю папку `sql`, сохранив вложенность, включая `05_packages/pkg_reports.pks` и `.pkb`.
- Новый `dist/OracleQuizPlatform.exe`.
- Для показа кода: `app`, `docs`, `README.md`, `requirements.txt`, `build/build_exe.ps1`.
- Docker, локальная `.venv`, кеши и временные файлы сборки для запуска готового EXE не нужны.

Папка `06_views` больше не поставляется. Не создавайте её вручную и не возвращайте
скрипты представлений из старой копии. Существующие даты миграций менять не нужно.

## Если база уже установлена

1. Закройте приложение у всех работающих с этой схемой пользователей.
2. Сделайте резервную копию данных принятым на сервере способом. DDL в Oracle
   фиксируется автоматически: единым ROLLBACK обновление модулей не отменяется.
3. Перенесите новую папку `sql` целиком, например в `C:\quiz_project\sql`.
4. В SQL Developer выберите кодировку UTF-8. Открытые ранее SQL-файлы закройте
   без сохранения и откройте заново. До исполнения убедитесь, что русский текст читается.
5. Через File → Open откройте именно сохранённый файл `sql/upgrade_no_views.sql`.
   Выберите подключение своей схемы и выполните **F5 / Run Script**.
6. В Script Output должны появиться `All Oracle objects are VALID.` и
   `Reports update complete; restart with the new client`. Не должно быть
   ошибок `ORA-`, `PLS-`, `SP2-` или `Warning: ... compilation errors`.
7. Выполните проверочные запросы из следующего раздела и запустите новый EXE.

Скрипт рассчитан на предыдущую актуальную схему с таймерами и лимитами попыток.
Он вызывает `upgrade_question_selection.sql`, добавляет недостающие поля подбора,
пересоздаёт зависимые пакеты, включая `pkg_reports`, и проверяет компиляцию.
Пользователи, хеши паролей, тесты, ответы и результаты не удаляются. Seed-скрипты
не запускаются. Повторный запуск допустим. Настройки подключения EXE не меняются.

**Не запускайте `install.sql` для обновления:** он удаляет старые объекты приложения
и данные. Если в старой схеме остались представления, новый клиент их не использует;
удалять их для запуска не требуется. Обновление намеренно их не удаляет, чтобы
не ломать сторонние запросы и старые подключения.

Если прежняя установка остановилась на CREATE VIEW, но таблицы, пакеты и seed-данные
уже присутствуют, обычно достаточно этого обновления. Если же отсутствуют таблицы
или исходные данные, сначала проверьте, на каком шаге произошла ошибка. Не выполняйте
полную установку поверх нужных данных только ради устранения сообщения об ошибке.

При `SP2-0310` проверьте расположение всех вложенных файлов. В SQL*Plus запускайте
из самой папки `sql`; одного абсолютного пути к `install.sql` недостаточно во всех клиентах:

```powershell
Set-Location 'C:\quiz_project\sql'
sqlplus /nolog
```

Используйте существующий TNS alias либо полный дескриптор с SID:

```sql
CONNECT KA2105_01@"(DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=10.22.10.64)(PORT=1521))(CONNECT_DATA=(SID=orcl)))"
@upgrade_no_views.sql
```

Форма полного дескриптора с SID приведена также в
[примере Oracle Ask TOM](https://asktom.oracle.com/pls/apex/f?p=100:11:0::::P11_QUESTION_ID:45033135081903).

Пароль вводится по приглашению SQL*Plus, не сохраняйте его в скриптах.

## Если схема новая

Вместо ручного запуска SQL Developer можно использовать кнопку
«Установить базу приложения (install.sql)» в новом EXE после ввода реквизитов схемы.
Она требует двойного подтверждения удаления данных и выполняет те же SQL-файлы,
уже встроенные в EXE. Не создаёт пользователя Oracle и не выдаёт ему права.
Подробно: [установка из приложения](11_installation_from_app.md).
Для существующей базы используйте безопасное обновление, не эту кнопку.

1. Убедитесь, что в ней нет данных проекта, которые требуется сохранить.
2. Проверьте права, квоту, кодировку и полную структуру `sql`.
3. Откройте `sql/install.sql` в SQL Developer и выполните F5 под своим пользователем.
4. Выполните `sql/tests/check_invalid_objects.sql` и, только для новой неизменённой
   установки, `sql/tests/seed_installation_test.sql`.
5. Запустите новый EXE, задайте доступные параметры БД и войдите в приложение.

На учебном сервере **не запускайте `create_schema_example.sql`**: пользователь уже
выдан преподавателем. Этот файл является примером для администратора собственной БД.

Создаются 3 аккаунта: `admin / Admin123!`, `author / Author123!`, `student / Student123!`;
3 теста, 18 вопросов и 24 сохранённых попытки. Эти пароли относятся только к новой
установке. При обновлении остаются ваши текущие пароли.

## Проверка пакета

```sql
SELECT object_name, object_type, status
FROM user_objects
WHERE object_name IN ('PKG_REPORTS', 'PKG_ADMIN', 'PKG_TESTING')
ORDER BY object_name, object_type;

SELECT name, type, line, position, text
FROM user_errors
ORDER BY name, sequence;

SELECT procedure_name
FROM user_procedures
WHERE object_name = 'PKG_REPORTS' AND procedure_name IS NOT NULL
ORDER BY procedure_name;
```

Ожидаются 6 строк PACKAGE/PACKAGE BODY со статусом VALID, отсутствие ошибок
компиляции и 7 процедур отчётности. В новой схеме `SELECT COUNT(*) FROM user_views`
вернёт 0; в обновлённой старые неиспользуемые представления могут остаться.

Пример прямого вызова без GUI, запускать как скрипт через F5:

```sql
VARIABLE report REFCURSOR;
BEGIN
    pkg_reports.leaderboard(:report);
END;
/
PRINT report;
```

Для проверки поведения выполните `reports_smoke_test.sql`, `comparison_smoke_test.sql`,
`server_logic_smoke_test.sql` и `question_selection_smoke_test.sql` из `sql/tests`.
Они создают собственные временные записи и откатывают их; требуется хотя бы один
активный администратор приложения. Полный актуальный список проверок приведён в карте БД.

В EXE проверьте каталог, «Мои результаты», карточку результата с пояснениями
и сравнение со средним, затем авторскую аналитику. Все вычисления остаются в Oracle.

## Что фактически проверено

На локальном Oracle Database Free 23c создана изолированная схема ровно с пятью
перечисленными правами, без дополнительных ролей и с квотой 300 МБ.
Пробная команда CREATE VIEW получила ORA-01031. Обе установки (`install.sql`
и Docker `install_modules.sql`) успешны; все объекты VALID и собственных views нет.
Восемь SQL smoke-тестов и проверка seed-данных успешны. Двойной запуск обновления
сохранил все строки всех 15 таблиц, в том числе хеши паролей.
Реальным драйвером Python проверены все 7 отчётов, 24 результата и 144 детализации.
Отдельно прошли 32 Python unit/GUI-теста. На самом учебном сервере проверка не выполнялась.
Страницы каталога, истории, результатов и студии проверены с реальной тестовой БД
для всех трёх ролей. Новый EXE успешно прошёл самопроверку и проверку подключения.
Эта проверка не означает отдельного тестирования на Oracle 18c или 21c.
