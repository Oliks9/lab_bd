# Отчет по выполненной работе

Дата обновления: 27.05.2026

## 1. Цель проекта

Разработать приложение для онлайн-квизов, в котором:

- серверная логика реализована в Oracle (SQL/PLSQL);
- Python используется как GUI и клиент вызова процедур;
- права доступа и критичные проверки выполняются в БД.

## 2. Выполненные задачи

### 2.1. Архитектура проекта

- Выделена модульная структура:
  - `sql/` — объекты Oracle (таблицы, функции, процедуры, триггеры, пакеты, представления, seed, миграции, тесты).
  - `app/quiz_client/` — GUI и слой доступа к Oracle.
  - `docker/` — автоматический запуск, проверка и обновление БД.
  - `build/` — сборка EXE.

### 2.2. Пользователи и безопасность

- Реализованы регистрация и вход через `pr_register_user` и `pr_login`.
- Введены роли `USER`, `AUTHOR`, `ADMIN`.
- Добавлен seed-администратор `admin`.
- Проверки прав выполняются в `pkg_admin`, а не в GUI.

### 2.3. Контент тестов

- Автор/администратор может создавать:
  - тематики;
  - категории;
  - тесты;
  - вопросы разных типов;
  - варианты ответов для option-вопросов.
- Для вопроса поддерживается редактирование (в черновике).
- При публикации теста Oracle валидирует корректность заполнения вопросов и вариантов.

### 2.4. Прохождение тестов

- Реализованы режимы таймера:
  - `QUIZ` — время на весь тест;
  - `QUESTION` — время на каждый вопрос.
- В режиме `QUESTION` при истечении времени вызывается `pkg_testing.expire_question` и выполняется автопереход к следующему вопросу.
- Итоги попытки рассчитываются в Oracle (`awarded_points`, `max_points`, `score_percent`).

### 2.5. Логика удаления и сбросов

- Автор может удалять свой тест и свои вопросы; администратор может удалять любой управляемый контент.
- При удалении теста удаляются связанные попытки (сброс статистики теста).
- При удалении вопроса:
  - удаляются связи в `attempt_questions`;
  - пересчитываются порядковые номера вопросов;
  - пересчитываются агрегаты попыток по оставшимся вопросам.
- Администратор может:
  - обнулить попытки пользователя по конкретному тесту;
  - обнулить весь прогресс пользователя.

### 2.6. Интерфейс

- Разделены экраны подключения, входа и регистрации.
- Переработаны экраны автора и администратора.
- В редакторе вопроса отображаются только релевантные поля по типу вопроса.
- После добавления тематик/категорий справочники в интерфейсе обновляются без повторного входа.
- В результатах теста показываются правильные ответы и пояснения автора при `show_feedback = 1`.

### 2.7. Инфраструктура и проверка

- Подготовлены Docker-сценарии:
  - `start.ps1` — первичная инициализация;
  - `upgrade.ps1` — обновление без потери данных;
  - `check.ps1` — проверка SQL smoke tests.
- Настроена сборка EXE через PyInstaller и зависимости `oracledb`/`cryptography`.

## 3. Исправления по замечаниям преподавателя

- Добавлены регистрация, вход, роль администратора по умолчанию.
- Расширены права администратора и автора для управления контентом.
- Добавлена возможность скрывать опубликованный тест обратно в черновик.
- Исправлена логика таймера с автопереходом по вопросам.
- Исправлен показ пояснений автора в итогах.
- Добавлены операции удаления вопросов/тестов с корректным пересчетом данных.

## 4. Результат

Проект доведен до состояния полноценного учебного приложения:

- основная логика реализована в Oracle;
- Python выполняет роль клиентского интерфейса;
- функциональность закрывает полный цикл: от авторинга тестов до аналитики и администрирования.
