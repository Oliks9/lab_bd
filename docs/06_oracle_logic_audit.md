# Проверка логики Oracle и Python

Дата: 09.09.2026. Проверены рабочие модули `app/quiz_client`, SQL-объекты и Docker-скрипты.
`reference/quiz_app_template.py` является исходным примером оформления и не входит в приложение.

## Распределение ответственности

| Возможность | Где выполняется бизнес-правило | Что делает Python |
| --- | --- | --- |
| Регистрация, пароль, активность аккаунта | `pr_register_user`, `pr_login`, `fn_hash_password`, `pkg_admin` | Передает поля формы, показывает ошибку |
| Роли и доступ к опубликованным тестам | `fn_can_access_quiz`, проверки `pkg_admin`, SQL с `app_users` | Отображает подходящие страницы и кнопки |
| Темы, категории, связь вопроса с тематикой | `pkg_admin`, внешние ключи и ограничения таблиц | Формы и выпадающие списки |
| Черновик, публикация, настройки | `pkg_admin`, проверки полноты вопросов, ограничение `DRAFT` | Собирает параметры и отправляет команды |
| Лимит попыток | `pkg_admin` проверяет допустимое значение, `pkg_testing.start_attempt` считает попытки | Преобразует ввод `0` в `NULL` |
| Одна активная попытка | `start_attempt`, блокировка строки пользователя | Показывает серверную ошибку |
| Состав теста | `start_attempt`, `attempt_questions`, `ROW_NUMBER` | Показывает полученные вопросы |
| Таймер | Время `SYSTIMESTAMP`, проверки `submit_answer` и `expire_question` | Показывает обратный отсчет и запрашивает переход |
| Шесть типов ответов | `pkg_testing.submit_answer` | Собирает выбранные ID или текст |
| Последовательность | Oracle сравнивает ID с `LISTAGG` по `seq_no` | Перемешивает карточки, обрабатывает перетаскивание |
| Завершение, баллы и проценты | `finish_attempt`, `fn_attempt_percent`, последний ответ вызывает завершение внутри пакета | Показывает результат |
| Незаконченные попытки при входе | `pr_login` вызывает `abandon_user_attempts` | Вызывает только вход |
| Пояснения и правильный ответ | `v_attempt_details`: завершенная попытка и `show_feedback=1` | Форматирует полученные поля |
| Статистика и пересчет после удаления | SQL-представления, агрегаты и `pkg_admin.delete_question` | Таблицы результатов |
| Удаление и отключение пользователей | Проверки `pkg_admin`, завершение активных попыток | Подтверждение действия и вызов процедуры |

SQL, записанный строкой в `database.py`, выполняется Oracle. Наличие `SELECT` в Python
не переносит расчеты на клиент. Форматирование дат, русских подписей, выбор вкладки,
перетаскивание и предварительная проверка заполнения формы относятся к интерфейсу.

## Исправления по результатам проверки

- Сервер отклоняет преждевременный вызов `expire_question` с `-20212`.
- GUI перед завершением отсчета повторно читает время БД; после перехода берет номер вопроса из Oracle.
- Остаток времени вычисляется SQL через интервалы с учетом долей секунды и округлением вверх.
- Последний ответ завершает попытку в обоих режимах времени; последний таймаут завершает ее как `EXPIRED`.
- Заброшенные попытки закрываются внутри `pr_login`, даже при вызове входа из SQL-клиента.
- `start_attempt` сериализует старты одного пользователя и проверяет отсутствие активной попытки и лимит.
- Повторный вызов `abandon_attempt` не превращает законченный результат в просроченный.
- Пояснения и правильные ответы маскируются на уровне view, а не только виджетов.
- Списки авторских тестов и статистика используют актуальную роль из БД.
- Целочисленный диапазон лимита попыток проверяется пакетом Oracle, независимо от формы.

## Проверка без GUI

`sql/tests/server_logic_smoke_test.sql` создает временные тест и учетную запись, затем
проверяет таймер, поздний ответ, лимиты, завершение, прямой вход через `pr_login`,
скрытие пояснений и повторную финализацию. В конце выполняется откат к savepoint.
Остальные smoke-тесты проверяют шесть типов ответов, роли, редактирование, удаление и статистику.

```powershell
powershell -ExecutionPolicy Bypass -File .\docker\check.ps1
```

## Границы архитектуры

Приложение подключается непосредственно владельцем схемы `quiz_app`. Это учебная
архитектура: владелец схемы имеет прямой доступ к таблицам, а API получает ID
пользователя параметром. Проверки процедур не являются защитой от человека,
который знает пароль схемы и выполняет произвольный SQL. Для такой защиты потребуются
отдельная учетная запись с правами только на API и доверенная серверная сессия приложения.

При обычном закрытии GUI отправляет `abandon_attempt`. Если процесс принудительно
убит или сеть недоступна, Oracle не получает это событие мгновенно: попытка будет
закрыта при следующем успешном входе. Фоновый `DBMS_SCHEDULER` или heartbeat не реализован.
Отсчет GUI инициирует запрос перехода, но допустимость перехода определяет Oracle.

## Подключение

- DSN: `localhost:1521/FREEPDB1`.
- Схема: `quiz_app`, пароль: `P@ssw0rd`.
- `docker/change_schema_password.ps1` меняет пароль уже существующей схемы через `ALTER USER`.
- `docker/upgrade.ps1` обновляет модули без удаления данных.
- Пароль схемы и пароль аккаунта приложения независимы. Смена схемы не меняет `app_users`.
