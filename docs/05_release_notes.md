# Release Notes

## 2026-09-18

- При новой установке создаются три опубликованных публичных теста: существующий Oracle и новые математика/русский язык. По шесть вопросов всех поддерживаемых типов, восемь баллов, пояснения включены.
- Добавлены начальные аккаунты `author / Author123!` (AUTHOR) и `student / Student123!` (USER); исходный администратор `admin / Admin123!` сохранён. Автор владеет двумя новыми тестами.
- Новый seed `03_subjects_and_users.sql` включён в обычную установку и Docker. Обновление существующей схемы не перезапускает seed и не сбрасывает пароли.
- Удалены комментарии и описательные Python-docstring из исходников, SQL, PowerShell и `.env.example`; исполняемые строки, SQL-запросы и пояснения к вопросам сохранены.
- Добавлена проверка `seed_installation_test.sql` для новой установки; она проверяет состав данных, авторизацию и прохождение всех трёх тестов, затем откатывает свои попытки.
- Оба установочных маршрута проверены в отдельной временной схеме Oracle: все объекты VALID, начальные данные соответствуют ожиданиям, существующие семь SQL smoke-тестов и 15 Python-тестов прошли. Рабочая схема не переустанавливалась.
- Обновлена документация начальных данных, ролей, установки и проверок. Удаление комментариев не меняет бизнес-логику.
- EXE пересобран; встроенная проверка драйвера Oracle, cryptography и Tkinter завершилась успешно (`EXE verified`).

## 2026-09-13

- Ошибка загрузки `oracledb` больше не маскируется под отсутствие самого пакета: клиент показывает исходный `ImportError`, включая ошибки зависимостей и DLL.
- Добавлен `app/quiz_client/diagnostics.py` и режим `--self-check <путь-к-JSON>` без подключения к Oracle. Проверяются Thin-драйвер, нативная криптография и Tkinter; сохраняются версии, пути и traceback ошибок.
- `cryptography` явно включена в `requirements.txt`. Сборщик проверяет выбранный Python, зависимости и готовый EXE; ошибка проверки останавливает сборочный сценарий.
- Путь к Python разрешается до смены рабочей папки; сборка и установка пакетов используют один интерпретатор. Временные настройки среды восстанавливаются после завершения скрипта.
- Добавлены шесть регрессионных тестов, всего 15 Python-тестов проходят. Локальный EXE прошёл проверку драйвера, криптографии и Tcl/Tk вне песочницы; удалённый Windows Server нужно проверять отдельно.
- Обновлены README и сценарии проверок; добавлена подробная инструкция `08_build_and_dependencies.md` для пересборки и диагностики на Windows.
- Данные и объекты Oracle не менялись. Повторный `install.sql` для этого обновления не нужен.

## 2026-09-12

- Исправлено обрезание нижней карточки каталога и кнопки «Начать выбранный тест»: место под действие резервируется до растягивания таблицы.
- Описание и название адаптируются к ширине карточки и прокручиваются отдельно от кнопки; статусы переносятся на следующую строку. Высота области описания уменьшается при нехватке места, сохраняя видимые строки таблицы.
- В каталоге добавлена прокрутка списка тестов и отключение кнопки запуска при пустом результате фильтра.
- Добавлены три GUI-регрессии каталога: размеры 1060x700, 1240x820, 1920x1080; масштабы Tk, соответствующие примерно 100/125/150/200%; длинный текст, фильтрация и запуск. Всего девять Python-тестов проходят.
- Для исправления отображения достаточно заменить EXE. Переустановка или обновление Oracle не нужны.

- После запуска Docker миграция подбора проверена на Oracle, включая повторный запуск: все объекты `VALID`, семь SQL-тестов проходят.
- Старые проверки часового пояса, шести типов ответов и сбросов больше не выбирают произвольный опубликованный тест: они создают свои временные данные. Добавлены уникальные имена и откат при ошибке.
- Шесть Python-тестов и открытие вкладки «Подбор» с реальной базой при 1060x700 также прошли проверку.

- Новая вкладка «Подбор»: все вопросы по порядку или случайные N из категории заданной сложности внутри выбранного теста.
- `pkg_admin.set_quiz_selection` сохраняет параметры черновика; `fn_quiz_pool_count` считает подходящие вопросы.
- `pkg_testing.start_attempt` выбирает и сохраняет случайный набор в Oracle; таймер и баллы используют этот набор.
- Публикация, старт и удаление вопросов защищены от недостаточного количества в наборе; фильтрованную категорию нельзя удалить.
- Каталог отображает N, категорию и сложность, не обещая фиксированную сумму баллов случайного набора.
- Добавлена повторно запускаемая миграция и обновление существующей схемы без SYS и удаления данных.
- Добавлены SQL-сценарий подбора и четыре автоматических GUI-теста. Инструкция: `07_question_selection.md`.

## 2026-09-11

- На экран результата добавлена карточка сравнения со средним: ваш процент, средний процент, разница в процентных пунктах и количество участников/попыток.
- Расчет полностью выполняется представлением Oracle `v_attempt_comparison`. Собственные попытки исключаются, каждая завершённая или прерванная попытка других пользователей имеет одинаковый вес.
- Обработаны отсутствие других результатов, нулевая оценка, незавершённая попытка и отсутствие баллов для оценки; графики не используются.
- Добавлен SQL-тест `comparison_smoke_test.sql`, подключенный к установке Docker, обновлению и проверкам.
- Для существующей схемы достаточно выполнить `sql/06_views/01_views.sql` и заменить EXE; данные не удаляются.

## 2026-09-09

- Статусы попыток в истории и результатах переведены на русский: `IN_PROGRESS` — «В процессе», `FINISHED` — «Завершена», `EXPIRED` — «Прервана» (истекло время или попытка закрыта досрочно). Коды статусов в Oracle сохранены.
- Удалены декоративные символы и вспомогательный словарь иконок с кнопок Python GUI.
- Пароль схемы `quiz_app` обновлен на `P@ssw0rd` в установке, проверках, подсказках и README.
- Добавлены `docker/change_schema_password.ps1` и `.sql` для смены пароля существующей схемы без переустановки.
- `pr_login` завершает прежние активные попытки внутри Oracle; порядок установки учитывает зависимость от `pkg_testing`.
- `start_attempt` блокирует строку пользователя до проверки лимита и отклоняет вторую активную попытку (`-20213`).
- `expire_question` проверяет время Oracle (`-20212` до дедлайна); GUI синхронизирует таймер и номер вопроса с БД.
- Последний ответ завершает попытку и рассчитывает результат на сервере в обоих режимах времени; последний таймаут дает `EXPIRED`.
- `abandon_attempt` не меняет ранее завершенные результаты при повторном вызове.
- `v_attempt_details` возвращает правильные ответы и пояснения только после завершения и при включенном `show_feedback`.
- Роль для авторских списков и статистики читается SQL-запросом из `app_users`, а не передается из Python.
- В Oracle добавлена проверка целочисленного лимита попыток 1–1000; `NULL` означает отсутствие лимита.
- Добавлены серверные smoke-тесты и отдельный документ аудита логики.

## 2026-05-27

## 1. Oracle: схема и бизнес-логика

- Реализована структурированная SQL-архитектура:
  - таблицы, индексы, функции, процедуры, триггеры, пакеты, представления, seed, миграции, тесты.
- Расширен `pkg_admin`:
  - управление публикацией и черновиками;
  - настройка `show_feedback`;
  - настройка `attempt_limit`;
  - удаление вопросов/тестов с корректным пересчетом зависимых данных;
  - создание авторов, назначение ролей;
  - сброс прогресса пользователя (по тесту/полный);
  - смена пароля пользователя администратором (`set_user_password`);
  - отключение/включение аккаунта пользователем `ADMIN` (`set_user_active`);
  - удаление пользователя с защитными ограничениями (`delete_user`).
- Расширен `pkg_testing`:
  - режимы таймера `QUIZ` и `QUESTION`;
  - серверный автопереход на следующий вопрос (`expire_question`);
  - корректная финализация попытки и расчет процентов.
