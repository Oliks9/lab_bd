# Release Notes

## 2026-09-11

- На экран результата добавлена карточка сравнения со средним: ваш процент, средний процент, разница в процентных пунктах и количество участников/попыток.
- Расчет полностью выполняется представлением Oracle `v_attempt_comparison`. Собственные попытки исключаются, каждая завершённая или прерванная попытка других пользователей имеет одинаковый вес.
- Обработаны отсутствие других результатов, нулевая оценка, незавершённая попытка и отсутствие баллов для оценки; графики не используются.
- Добавлен SQL-тест `comparison_smoke_test.sql`, подключенный к установке Docker, обновлению и проверкам.
- Для существующей схемы достаточно выполнить `sql/06_views/01_views.sql` и заменить EXE; данные не удаляются.

## 2026-09-09

- Статусы попыток в истории и результатах переведены на русский: `IN_PROGRESS` — «В процессе», `FINISHED` — «Завершена», `EXPIRED` — «Прервана» (истекло время или попытка закрыта досрочно). Коды статусов в Oracle сохранены.
- Удалены декоративные символы и вспомогательный словарь иконок с кнопок Python GUI.
- Пароль схемы `quiz_app` обновлен на `P@ssw0rd` в установке, проверках, подсказках и README.
- Добавлены `docker/change_schema_password.ps1` и `.sql` для смены пароля существующей схемы без переустановки.
- `pr_login` завершает прежние активные попытки внутри Oracle; порядок установки учитывает зависимость от `pkg_testing`.
- `start_attempt` блокирует строку пользователя до проверки лимита и отклоняет вторую активную попытку (`-20213`).
- `expire_question` проверяет время Oracle (`-20212` до дедлайна); GUI синхронизирует таймер и номер вопроса с БД.
- Последний ответ завершает попытку и рассчитывает результат на сервере в обоих режимах времени; последний таймаут дает `EXPIRED`.
- `abandon_attempt` не меняет ранее завершенные результаты при повторном вызове.
- `v_attempt_details` возвращает правильные ответы и пояснения только после завершения и при включенном `show_feedback`.
- Роль для авторских списков и статистики читается SQL-запросом из `app_users`, а не передается из Python.
- В Oracle добавлена проверка целочисленного лимита попыток 1–1000; `NULL` означает отсутствие лимита.
- Добавлены серверные smoke-тесты и отдельный документ аудита логики.

## 2026-05-27

## 1. Oracle: схема и бизнес-логика

- Реализована структурированная SQL-архитектура:
  - таблицы, индексы, функции, процедуры, триггеры, пакеты, представления, seed, миграции, тесты.
- Расширен `pkg_admin`:
  - управление публикацией и черновиками;
  - настройка `show_feedback`;
  - настройка `attempt_limit`;
  - удаление вопросов/тестов с корректным пересчетом зависимых данных;
  - создание авторов, назначение ролей;
  - сброс прогресса пользователя (по тесту/полный);
  - смена пароля пользователя администратором (`set_user_password`);
  - отключение/включение аккаунта пользователем `ADMIN` (`set_user_active`);
  - удаление пользователя с защитными ограничениями (`delete_user`).
- Расширен `pkg_testing`:
  - режимы таймера `QUIZ` и `QUESTION`;
  - серверный автопереход на следующий вопрос (`expire_question`);
  - корректная финализация попытки и расчет процентов.

## 2. Миграции

- Добавлена миграция режима таймера теста/вопроса.
- Добавлена миграция timezone-aware полей попыток (`TIMESTAMP WITH TIME ZONE`).
- Добавлена миграция для `ORDERING` в option-based режим.
- Добавлена миграция лимита попыток на пользователя.

## 3. GUI и UX

- Улучшена структура экранов входа/регистрации и рабочих вкладок.
- Добавлены отдельные админ-действия:
  - смена пароля пользователя;
  - удаление пользователя;
  - сброс прогресса.
- Исправлены проблемы обновления UI после операций редактирования.
- Улучшено отображение и взаимодействие с ответами, включая `ORDERING`.

## 4. Качество и проверка

- Добавлены/обновлены smoke-тесты для:
  - авторизации;
  - контент-менеджмента;
  - прохождения тестов;
  - таймзон;
  - валидности Oracle-объектов.
- Сборка desktop-клиента в `dist/OracleQuizPlatform.exe` выполняется через `build/build_exe.ps1`.
