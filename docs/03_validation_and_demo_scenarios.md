# Проверка и сценарии демонстрации

Дата актуализации: 12.09.2026

## 1. Цель проверок

Подбор N по категории и сложности проверяется файлом `sql/tests/question_selection_smoke_test.sql`.
Сценарий GUI и пошаговое обновление схемы приведены в `07_question_selection.md`.

Состояние локальной проверки 12.09.2026: Docker запущен, контейнер Oracle имеет статус `healthy`.
Миграция подбора применена, повторный запуск `docker/upgrade.ps1` также успешен.
Все объекты Oracle имеют статус `VALID`, все семь SQL smoke-тестов и шесть Python-тестов
(GUI и транзакционная обёртка) проходят. Проверена вкладка «Подбор» с реальной базой
при размере окна 1060x700. Старые SQL-проверки теперь создают собственные временные тесты,
поэтому не зависят от наличия или изменения демонстрационного теста. Временные данные
откатываются и при успехе, и при ошибке; уникальные имена исключают конфликты с рабочими данными.

Подтвердить, что:

- Oracle-объекты корректно установлены и валидны;
- серверная бизнес-логика работает независимо от GUI;
- ключевые сценарии (авторинг, публикация, прохождение, удаление, администрирование) выполняются без потери консистентности.

## 2. Подготовка окружения

1. Поднять БД и приложение:
   - `powershell -ExecutionPolicy Bypass -File .\docker\start.ps1`
2. При необходимости обновить схему:
   - `powershell -ExecutionPolicy Bypass -File .\docker\upgrade.ps1`
3. Прогнать SQL smoke-тесты:
   - `powershell -ExecutionPolicy Bypass -File .\docker\check.ps1`

## 4. Матрица ручной проверки ключевой логики

### Каталог: нижняя панель и масштабирование

Выполните `python -m unittest discover -s app/tests -v` с `app` в `PYTHONPATH` и рабочим Tk.
Для среды проекта с bundled-runtime используйте настройки из `build/build_exe.ps1`.
Все девять Python-тестов проходят, включая три проверки `test_catalog_layout.py`.

1. Откройте каталог при 1060x700, 1240x820 и 1920x1080. Кнопка «Начать выбранный тест» должна быть полностью видна и доступна, строки списка также должны оставаться видимыми.
2. Проверьте с повышенным масштабом Windows. Автотесты меняют масштаб Tk примерно от 100% до 200%; ручная проверка на целевом мониторе дополнительно проверяет масштабирование всей ОС.
3. Выберите тест с длинным названием/описанием или подбором вопросов. Вся информация доступна через полосу прокрутки и колесо мыши внутри карточки, кнопка запуска не прокручивается вместе с ней.
4. Выберите пустую тематику: кнопка запуска отключается. Вернитесь ко всем тематикам: выбранный тест снова можно запустить кнопкой или Enter.

Исправление меняет только GUI: для другого компьютера достаточно нового EXE, данные Oracle переустанавливать не нужно.

| Сценарий | Шаги | Ожидаемый результат |
|---|---|---|
| Регистрация пользователя | Заполнить форму регистрации и войти | Успешный вход с ролью `USER` |
| Создание автора | Войти под `admin`, создать автора в разделе «Команда» | Новый пользователь получает роль `AUTHOR` |
| Создание тематики/категории | Войти под `AUTHOR`, добавить тему и категорию | Новые записи сразу доступны в UI без повторного входа |
| Создание черновика теста | Автор создает тест и задает `timer_mode`, `attempt_limit`, `show_feedback` | Тест в `DRAFT`, настройки сохранены |
| Редактирование вопроса | Добавить вопрос, затем открыть и изменить поля | Изменения сохранены, старые options заменены при смене типа |
| Публикация теста | Нажать «Опубликовать» | Публикация проходит только при валидной структуре вопросов |
| Возврат в черновик | Для опубликованного теста нажать «Скрыть в черновик» | Статус снова `DRAFT`, доступно редактирование |
| Ограничение попыток | Установить `attempt_limit=1`, пройти тест 2 раза | Вторая попытка блокируется ошибкой лимита |
| Таймер `QUESTION` | Запустить тест с таймером на вопрос, дождаться таймаута | Происходит автопереход к следующему вопросу |
| Показ пояснений | Включать/выключать `show_feedback`, пройти тест | В результате пояснения показываются только при `show_feedback=1` |
| Удаление вопроса | В черновике удалить вопрос | Пересчитаны `seq_no`, статистика попыток и проценты |
| Удаление теста | Удалить тест автора | Тест удален, связанные попытки удалены |
| Сброс по тесту | Под `ADMIN` вызвать сброс попыток пользователя по тесту | У пользователя нет попыток по выбранному тесту |
| Полный сброс | Под `ADMIN` выполнить полный сброс прогресса | У пользователя отсутствуют все попытки |
| Смена пароля | Под `ADMIN` сменить пароль пользователю | Пользователь входит только с новым паролем |
| Отключение/включение аккаунта | Под `ADMIN` отключить пользователя, затем включить обратно | В отключенном состоянии вход запрещен, после включения вход снова доступен |
| Удаление пользователя | Под `ADMIN` удалить пользователя не `ADMIN` | Пользователь и его зависимые данные очищены |

## 5. Проверка по PL/SQL API (без GUI)

Рекомендуется демонстрировать преподавателю, что логика живет в БД:

1. `pr_register_user` / `pr_login`.
2. `pkg_admin.create_topic`, `create_category`, `create_quiz`.
3. `pkg_admin.add_question`, `add_option`, `publish_quiz`.
4. `pkg_testing.start_attempt`, `submit_answer`, `finish_attempt`.
5. `pkg_admin.delete_question` / `delete_quiz`.
6. `pkg_admin.reset_user_quiz_attempts` / `reset_user_progress`.

Если вызвать недопустимую операцию, Oracle должен вернуть `RAISE_APPLICATION_ERROR` с соответствующим кодом.

## 9. Сравнение со средними (11.09.2026)

1. Создайте тест с пятью вопросами по одному баллу и разрешите повторное прохождение.
2. Пройдите тест участником А на 60%, участником Б на 40%.
3. Пройдите тот же тест участником В на 80%. В результате должны быть среднее 50%, разница +30 п. п., два участника и две попытки в сравнении.
4. Повторно пройдите тест участником В на 0%. Среднее для В останется 50%; разница новой попытки будет -50 п. п.
5. Проверьте случай одинакового результата со средним и случай без результатов других участников. Отсутствие выборки не должно отображаться как среднее 0%.
6. Сбросьте результаты А и Б через администратора и повторно откройте результат В. Должно появиться сообщение об отсутствии других результатов.

Незавершённые попытки и попытки без положительного максимального балла не участвуют
в среднем; прерванные попытки с оценкой участвуют. Собственные повторные прохождения
исключаются полностью. Подробности правил и округления: `02_database_logic_map.md`, раздел 11.6.

Автоматическая SQL-проверка: `sql/tests/comparison_smoke_test.sql` (F5 в SQL Developer).
На уже установленном учебном сервере сначала выполните `sql/06_views/01_views.sql`,
затем проверку и замените EXE. Повторная полная установка не нужна.
