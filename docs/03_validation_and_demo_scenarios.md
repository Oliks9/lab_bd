# Проверка и сценарий демонстрации

## 1. Быстрый запуск

1. Поднять Oracle в Docker:
   `powershell -ExecutionPolicy Bypass -File .\docker\start.ps1`
2. Применить обновления к существующей базе:
   `powershell -ExecutionPolicy Bypass -File .\docker\upgrade.ps1`
3. Выполнить проверку:
   `powershell -ExecutionPolicy Bypass -File .\docker\check.ps1`

## 2. Сборка EXE

Команда сборки:

`powershell -ExecutionPolicy Bypass -File .\build\build_exe.ps1 -Python .\.venv\Scripts\python.exe`

Результат:

- `dist\OracleQuizPlatform.exe`

## 3. Что проверяют SQL smoke tests

- `check_invalid_objects.sql`: все объекты Oracle должны быть в статусе `VALID`.
- `timezone_smoke_test.sql`: проверка корректной работы времени с часовыми поясами.
- `auth_smoke_test.sql`: регистрация, вход, создание автора.
- `content_management_smoke_test.sql`: управление контентом и сбросы прогресса.
- `smoke_test.sql`: прохождение теста по всем типам вопросов и проверка расчета результата.

## 4. Рекомендуемый сценарий защиты

1. Войти под `admin / Admin123!`.
2. Создать автора через вкладку команды.
3. Войти под автором и создать новую тематику, категорию и тест.
4. При создании теста показать выбор режима таймера:
   `На весь тест` и `На каждый вопрос`.
5. Добавить вопросы разных типов.
6. Опубликовать тест.
7. Войти под обычным пользователем и пройти тест:
   в режиме `QUESTION` показать автопереход на следующий вопрос после тайм-аута.
8. Открыть результат:
   показать правильные ответы и пояснения автора при включенном `show_feedback`.
9. Под администратором показать сброс попыток по одному тесту и полный сброс прогресса.

## 5. Критерии готовности

- Логика проверки, таймера и ролей выполняется в Oracle.
- GUI работает как клиент, не дублируя бизнес-правила в Python.
- Проект запускается через Docker, проходит smoke tests и собирается в EXE.
