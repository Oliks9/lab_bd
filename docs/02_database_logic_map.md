# Карта серверной логики Oracle

## 1. Принцип

Python-клиент не содержит критичной логики проверки теста. Он вызывает процедуры и читает представления Oracle.  
Вся проверка ответов, таймеры, права и итоговый расчет выполняются в БД.

## 2. Где находится логика

- Таблицы: `sql/01_tables/01_tables.sql`
- Функции: `sql/02_functions/`
- Процедуры входа/регистрации: `sql/03_procedures/`
- Триггеры валидации и аудита: `sql/04_triggers/`
- Пакеты бизнес-логики: `sql/05_packages/`
- Отчетные представления: `sql/06_views/01_views.sql`
- Seed-данные: `sql/07_seed/`
- Миграции без потери данных: `sql/08_migrations/`

## 3. Основные пакеты

### `pkg_admin`

Отвечает за административную и авторскую часть:

- Создание тематик и категорий.
- Создание тестов.
- Добавление и редактирование вопросов.
- Публикация тестов.
- Выдача доступа к закрытым тестам.
- Удаление/архивация контента.
- Сброс пользовательского прогресса.
- Создание авторов и управление ролями.

### `pkg_testing`

Отвечает за прохождение теста:

- `start_attempt` создает попытку и формирует набор вопросов.
- `submit_answer` принимает ответ, валидирует и начисляет баллы.
- `expire_question` делает автопропуск вопроса по таймеру (режим `QUESTION`).
- `finish_attempt` фиксирует финальный статус и результат попытки.

## 4. Таймеры (реализованы в Oracle)

### Режим `QUIZ`

- При старте попытки заполняется `attempts.deadline_at`.
- Если дедлайн превышен, попытка завершается со статусом `EXPIRED`.

### Режим `QUESTION`

- В попытке хранятся `active_question_order`, `question_started_at`, `question_duration_minutes`.
- По истечении времени вопроса вызывается `pkg_testing.expire_question`:
- Текущий вопрос помечается как пропущенный (без ответа).
- Активный указатель сдвигается на следующий вопрос.
- На последнем вопросе попытка завершается штатно.

## 5. Почему это соответствует теме "программирование в БД"

- Ключевые бизнес-правила находятся в пакетах PL/SQL, а не в GUI.
- Используются ограничения, триггеры, представления и серверные процедуры.
- Контроль ролей и доступов выполняется в БД.
- GUI выступает thin-client слоем над Oracle.
