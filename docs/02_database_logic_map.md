# Карта серверной логики Oracle

## 1. Базовый принцип

Python-клиент выступает тонкой оболочкой: он вызывает процедуры/пакеты Oracle и отображает результаты.  
Критичная логика (права, таймеры, проверка ответов, расчеты, удаления) выполняется в БД.

## 2. Расположение логики по каталогам

- `sql/01_tables/` — схема, внешние ключи, check-ограничения.
- `sql/02_functions/` — вспомогательные функции (`fn_hash_password`, `fn_can_access_quiz`, `fn_attempt_percent`).
- `sql/03_procedures/` — процедуры регистрации/входа (`pr_register_user`, `pr_login`).
- `sql/04_triggers/` — технические триггеры валидации и аудита.
- `sql/05_packages/` — бизнес-операции (`pkg_admin`, `pkg_testing`).
- `sql/06_views/` — представления для каталога, истории, деталей, статистики, рейтинга.
- `sql/07_seed/` — справочники и стартовые данные.
- `sql/08_migrations/` — миграции обновления схемы без потери данных.
- `sql/tests/` — smoke tests.

## 3. Пакет `pkg_admin`

Ответственность:

- управление тематиками и категориями;
- создание/редактирование тестов и вопросов;
- публикация теста и выдача доступа;
- удаление тестов/вопросов/категорий/тематик;
- перевод опубликованного теста обратно в черновик (`archive_quiz` -> статус `DRAFT`);
- управление ролями и создание авторов;
- сброс прогресса пользователей.

Ключевые правила:

- `require_editor` — операции авторинга доступны только `AUTHOR`/`ADMIN`;
- `require_quiz_owner` — редактирование теста только для владельца (или администратора) и только в `DRAFT`;
- `require_quiz_manager` — удаление теста/вопросов только владельцем или администратором;
- `delete_quiz` удаляет связанные попытки;
- `delete_question` удаляет вопрос, пересчитывает порядки и агрегаты попыток;
- `delete_question` блокируется при активных попытках (`IN_PROGRESS`) по тесту.

## 4. Пакет `pkg_testing`

Ответственность:

- `start_attempt` — старт попытки и формирование набора вопросов.
- `submit_answer` — прием ответа, проверка, начисление баллов.
- `expire_question` — автопереход к следующему вопросу в режиме `QUESTION`.
- `finish_attempt` — завершение попытки и финальный расчет результата.

Особенности:

- Таймеры хранятся и считаются на сервере (`TIMESTAMP WITH TIME ZONE`).
- В режиме `QUESTION` попытка ведет `active_question_order`, `question_started_at`, `question_duration_minutes`.
- Проверка корректности ответов для option-вопросов выполняется в БД, включая валидацию набора option id.

## 5. Триггеры и аудит

- `trg_attempts_biu` проверяет корректность дат попытки.
- `trg_quizzes_biu` нормализует и обновляет поля времени.
- `trg_audit_users` и `trg_audit_attempts` пишут события в `audit_log`.
- Операции сброса прогресса (`reset_user_quiz_attempts`, `reset_user_progress`) также пишут аудит.

## 6. Представления аналитики

- `v_quiz_catalog` — каталог тестов с агрегатами.
- `v_attempt_history` — история попыток пользователя.
- `v_attempt_details` — детализация по вопросам и ответам.
- `v_question_statistics` — статистика по вопросам.
- `v_leaderboard` — рейтинг пользователей.

## 7. Поток выполнения операций

1. GUI вызывает `OracleGateway` метод.
2. Метод вызывает Oracle-процедуру/пакет.
3. Oracle проверяет права и бизнес-ограничения.
4. Oracle обновляет данные/представления.
5. GUI читает обновленные данные и перерисовывает экран.

## 8. Соответствие теме «программирование в базах данных»

- Центральные бизнес-правила реализованы в PL/SQL.
- Используются процедуры, пакеты, триггеры, функции, представления и ограничения.
- Python не хранит дубли бизнес-логики, а только отображает и маршрутизирует вызовы.
