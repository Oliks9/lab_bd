# Oracle Quiz Platform

## Назначение программы

Oracle Quiz Platform предназначена для создания и прохождения тестов, проверки
ответов и просмотра результатов. Пользователь работает через приложение для Windows.
Данные и основная логика приложения находятся в Oracle: управление доступом,
ограничения попыток, таймеры, проверка ответов, подсчёт баллов и отчёты.

## 1. Состав комплекта

```text
OracleQuizPlatform_Release/
  OracleQuizPlatform.exe    приложение для Windows
  README.md                 инструкция по установке и использованию
  rebuild.ps1               пересборка приложения
  publish_gitlab.ps1         загрузка комплекта в GitLab без установленного Git
  upload_gitlab.cmd          запуск загрузки двойным щелчком с сохранением окна
  requirements.txt          зависимости для пересборки и запуска исходников
  app/                      исходный код интерфейса и подключения к Oracle
  build/                    скрипт сборки EXE
  sql/                      установка и обновление объектов базы данных
```

Переносите папку целиком. Например, разместите её в `C:\OracleQuizPlatform_Release`.
Если комплект находится в архиве, сначала полностью распакуйте его.
Для просмотра исходного кода используйте папки `app` и `sql`.

## 2. Что необходимо для запуска

- Компьютер с Windows x64.
- Доступный сервер Oracle с запущенной базой данных.
- Заранее созданный пользователь схемы Oracle, его пароль и параметры подключения.
- Права и свободная квота для создания объектов приложения в этой схеме.

Для запуска готового EXE установка Python не требуется. SQL Developer нужен только
при выборе ручного способа установки или для просмотра объектов базы данных.
Само приложение не устанавливает сервер Oracle, не создаёт пользователя схемы
и не выдаёт ему права. Это должно быть подготовлено администратором базы данных.

### Права пользователя схемы

Необходимы следующие привилегии:

```text
CREATE SESSION
CREATE TABLE
CREATE SEQUENCE
CREATE PROCEDURE
CREATE TRIGGER
```

Для учебного развёртывания предусмотрена квота 300 МБ в табличном пространстве
пользователя. В нём должно оставаться свободное место. Право `CREATE VIEW` не требуется.
Используйте выделенную для приложения схему, а не `SYS`, `SYSTEM` или `PDBADMIN`.

При необходимости выполните в SQL Developer под своим пользователем:

```sql
SELECT USER FROM dual;
SELECT privilege FROM session_privs ORDER BY privilege;
SELECT default_tablespace FROM user_users;
SELECT tablespace_name, bytes, max_bytes FROM user_ts_quotas;
```

Эти запросы только показывают сведения. Недостающие права и квоту выдаёт администратор
базы данных. Значение квоты 300 МБ в байтах равно `314572800`.

## 3. Параметры подключения

Запустите `OracleQuizPlatform.exe`. На первом экране заполните поля:

| Поле | Что указать |
| --- | --- |
| Сервер | Адрес или имя сервера Oracle |
| Порт | Порт подключения, обычно `1521` |
| Тип подключения | `SID` или «Имя службы» согласно выданным реквизитам |
| SID / имя службы | Идентификатор экземпляра или имя службы Oracle |
| Пользователь схемы | Имя вашего пользователя Oracle |
| Пароль схемы | Пароль этого пользователя Oracle |

Если у вас уже есть рабочее подключение в SQL Developer, используйте те же значения.
SID и имя службы не являются взаимозаменяемыми. Для сложной конфигурации можно
воспользоваться режимом ввода готовой строки подключения DSN.

**Не путайте пользователя схемы и пользователя приложения.** Сначала приложение
подключается к Oracle, затем открывается вход под логином `admin`, `author`, `student`
или самостоятельно зарегистрированным аккаунтом.

## 4. Первая установка схемы через EXE

Это основной способ развёртывания. SQL-скрипты уже включены в EXE.

**Важно: установка с нуля удаляет существующие данные проекта в выбранной схеме,
включая аккаунты приложения, тесты, ответы и результаты. Для обычного запуска
или обновления выполнять её нельзя.**

1. Убедитесь, что выбрана правильная схема и в ней нет данных проекта, которые нужно сохранить.
2. Заполните параметры подключения на первом экране приложения.
3. Нажмите «Установить базу приложения (install.sql)».
4. Прочитайте предупреждение и подтвердите установку вводом имени схемы.
5. Дождитесь успешного завершения в окне установки.
6. Закройте окно установки и нажмите «Подключиться».
7. Войдите в приложение, используя один из начальных аккаунтов из раздела 6.

Установщик проверяет доступность SQL-файлов, подключение, права и свободную квоту.
Во время установки не закрывайте приложение и не отключайте сеть. Другие экземпляры
приложения не должны работать с этой схемой в процессе переустановки.

При ошибке установка останавливается, а сообщение указывает файл и строку.
Уже выполненные операции создания и удаления объектов нельзя полностью отменить.
Повторяйте установку только после устранения причины и только если удаление данных допустимо.
Пароль пользователя схемы Oracle установка не изменяет.

Если несколько компьютеров используют одну и ту же схему, установка выполняется
один раз. На остальных компьютерах достаточно подключиться к ней.

## 5. Альтернативная установка через SQL Developer

Этот способ используется вместо установки через EXE. Последовательно выполнять
оба способа не нужно: повторная установка удалит ранее созданные данные проекта.

1. Откройте подключение к своей схеме в SQL Developer с ролью `Default`.
2. В `Tools → Preferences → Environment` выберите `Encoding = UTF-8`.
3. Если файл уже открыт, после смены кодировки закройте его и откройте заново.
4. Через `File → Open` откройте `sql/install.sql` из распакованного комплекта.
5. Выберите подключение к нужной схеме и нажмите `F5` (Run Script), не `Ctrl+Enter`.
6. Проверьте вывод: не должно быть ошибок `ORA-`, `PLS-` или `SP2-`.
7. Выполните `sql/check_installation.sql` через `F5`. Ожидается сообщение
   `All Oracle objects are VALID` без сообщений об ошибках.
8. Запустите EXE, заполните реквизиты схемы и нажмите «Подключиться».

Не переносите один `install.sql` без остальных файлов папки `sql` и не копируйте
его текст в пустую вкладку. Он подключает остальные скрипты по относительным путям.
Одного итогового сообщения об успехе недостаточно, если выше в выводе были ошибки.
Проверка установки обнаруживает как невалидные, так и отсутствующие обязательные объекты.

При использовании SQL*Plus сначала перейдите в папку `sql`, затем откройте SQL*Plus,
подключитесь к своей схеме и выполните `@install.sql`. Пример перехода в PowerShell:

```powershell
Set-Location 'C:\OracleQuizPlatform_Release\sql'
```

Если вложенные файлы не находятся, проверьте рабочую папку и целостность комплекта
либо используйте установку через EXE, которая не зависит от рабочей папки.
Если русский текст в SQL отображается неправильно, не запускайте скрипт до исправления
кодировки. Смена кодировки не исправляет уже повреждённые данные в базе.

## 6. Первый вход и начальные данные

После установки с нуля доступны следующие аккаунты приложения:

| Логин | Пароль | Роль |
| --- | --- | --- |
| `admin` | `Admin123!` | Администратор |
| `author` | `Author123!` | Автор |
| `student` | `Student123!` | Участник |

Это не реквизиты подключения к схеме Oracle. Начальные пароли рекомендуется сменить
через административные функции. При обновлении уже установленной базы сохраняются
прежние аккаунты и пароли, поэтому указанные значения могут к ней не подходить.

При первой установке создаются три демонстрационных теста:

- Oracle: основы серверной логики.
- Математика: базовые знания.
- Русский язык: базовые знания.

В каждом тесте шесть вопросов разных типов. Также сохраняются 24 демонстрационные
попытки и 144 ответа: у `author` и `student` по 12 прохождений.
Эти данные позволяют сразу открыть результаты и статистику.

## 7. Обычный запуск и регистрация

1. Откройте `OracleQuizPlatform.exe`.
2. Проверьте параметры схемы, введите её пароль и нажмите «Подключиться».
3. На странице входа введите логин и пароль аккаунта приложения.
4. Чтобы создать аккаунт участника, перейдите со страницы входа к регистрации,
   заполните форму, затем войдите под новым логином.

**При последующих запусках устанавливать схему заново не нужно.**
Для выхода из аккаунта используйте кнопку «Выйти».

## 8. Возможности программы

### Участник

- Просмотр доступных тестов и фильтрация по тематике.
- Прохождение публичных тестов и закрытых тестов, к которым выдан доступ.
- Сохранение ответов и получение баллов и процента выполнения.
- Просмотр истории попыток и сравнение своего результата со средним.
- Просмотр правильных ответов и пояснений после завершения, если это разрешил автор.

Для начала выберите тест в каталоге, ознакомьтесь с условиями и начните попытку.
Во время прохождения отвечайте на вопросы и нажимайте «Сохранить ответ и дальше».
После перехода к следующему вопросу вернуться к предыдущему нельзя.
Лимит попыток и ограничения времени задаёт автор. При таймере на отдельный вопрос
по истечении времени приложение автоматически переходит дальше.

### Автор

Работа выполняется в разделе «Студия тестов».

1. Подготовьте тематику и категорию вопросов.
2. Создайте тест, задайте название, описание и условия прохождения.
3. Добавьте вопросы, правильные ответы, баллы, сложность и пояснения.
4. При необходимости настройте подбор N вопросов по категории и сложности
   из вопросов этого же теста.
5. Выберите ограничение времени: на весь тест или на каждый вопрос отдельно.
6. Установите лимит попыток пользователя. Значение `0` означает отсутствие лимита.
7. Укажите, показывать ли правильные ответы и пояснения после завершения.
8. Выберите публичный доступ или доступ по приглашению и опубликуйте тест.

Для изменения настроек опубликованного теста сначала верните его в черновик.
После редактирования опубликуйте повторно. Автор может редактировать и удалять
свои тесты и вопросы, а также просматривать статистику прохождений.
Удаление теста удаляет связанные попытки и результаты: подтверждайте его внимательно.

### Типы вопросов

| Тип | Как пользователь отвечает |
| --- | --- |
| Один вариант | Выбирает один ответ; автор задаёт один правильный вариант |
| Несколько вариантов | Отмечает несколько ответов; автор задаёт не менее двух правильных вариантов |
| Текст | Вводит текстовый ответ |
| Число | Вводит числовой ответ |
| Верно / неверно | Выбирает одно из двух утверждений |
| Последовательность | Расставляет элементы по порядку, в том числе перетаскиванием мышью |

### Доступ к закрытым тестам

Во вкладке «Публикация» выберите нужный тест. Для закрытого теста можно выдать доступ
конкретным пользователям, просмотреть список имеющих доступ и отозвать приглашение.
Список обновляется после изменения без повторного входа.

Отзыв приглашения запрещает новые попытки, но не удаляет сохранённые результаты
и не прекращает уже начатую попытку. Автор теста и администратор имеют доступ по роли;
кнопка отзыва приглашения не отменяет эти права.

### Администратор

Администратору доступны управление содержимым и дополнительные функции:

- Создание аккаунтов авторов и изменение ролей пользователей.
- Смена пароля пользователя.
- Отключение и повторное включение аккаунтов, удаление пользователей.
- Сброс попыток пользователя по конкретному тесту или полного прогресса.
- Управление тематиками, категориями, тестами и вопросами.
- Просмотр результатов и статистики.

Отключение аккаунта запрещает вход без удаления его данных. Удаление аккаунта,
теста или сброс прогресса могут привести к потере результатов; проверяйте выбранный
объект перед подтверждением действия.

### Отчёты и управление интерфейсом

Приложение показывает результат попытки, историю прохождений, статистику вопросов
и сравнение результата пользователя со средним. Пояснения участнику показываются
только при соответствующей настройке автора.

Если содержимое не помещается, используйте прокрутку и изменение размера окна.
Клавиша `Tab` переключает поля. `Enter` выполняет основное действие на странице
входа и при подтверждении ответа во время прохождения.

## 9. Обновление программы и сохранение данных

Данные хранятся в Oracle, а не внутри EXE. Замена EXE не переносит и не удаляет их.
Перед обновлением сохраните резервную копию базы способом, согласованным с её администратором.

Если меняется только интерфейс, закройте приложение и замените EXE.
Если новая версия требует изменения объектов базы, необходимо также выполнить
подходящий скрипт обновления из папки `sql`:

| Состояние базы | Скрипт |
| --- | --- |
| Уже есть режимы таймера, лимиты попыток, подбор вопросов и `pkg_reports`; нужно обновить управление доступом | `upgrade_quiz_invitations.sql` |
| Более ранняя версия с представлениями, где уже есть режимы таймера и лимиты попыток | `upgrade_no_views.sql` |

Откройте выбранный скрипт в SQL Developer с кодировкой UTF-8 и выполните через `F5`,
затем запустите `check_installation.sql`. Не выполняйте все скрипты подряд.
Для произвольной старой базы сначала уточните её структуру и подходящий порядок обновления.

**Не используйте `install.sql` для обновления: он удаляет прежние данные проекта.**
При подключении нового компьютера к уже установленной схеме повторная установка не нужна.
Для переноса накопленных данных на другой сервер требуется отдельный экспорт и импорт базы.

## 10. Пересборка EXE

Этот раздел нужен только при изменении исходного кода или SQL внутри приложения.
Для обычного запуска готового EXE перечисленные действия не нужны.

1. Установите Python 3.12 x64 с компонентами pip, Tcl/Tk и Python Launcher.
2. Обеспечьте доступ к интернету для загрузки зависимостей.
3. Убедитесь, что в комплекте есть `app`, `sql`, `build`, `requirements.txt` и `rebuild.ps1`.
4. Закройте работающий EXE и откройте PowerShell в корне релизной папки.
5. Выполните:

```powershell
py -3.12 --version
powershell -ExecutionPolicy Bypass -File .\rebuild.ps1
```

Скрипт установит зависимости, соберёт и проверит приложение, затем заменит
`OracleQuizPlatform.exe` в той же папке. При ошибке сборки или самопроверки старый
EXE не заменяется. Для замены файл должен быть закрыт, а папка доступна для записи.

При отсутствии Python Launcher укажите фактический путь к Python. Пример:

```powershell
powershell -ExecutionPolicy Bypass -File .\rebuild.ps1 -Python 'C:\Python312\python.exe'
```

Дополнительное окружение автоматически не создаётся: зависимости устанавливаются
в выбранный Python. Промежуточные файлы и отчёты помещаются в
`%TEMP%\OracleQuizPlatform-build-<идентификатор>`; путь выводится при сборке.
После успешной проверки эти временные файлы можно удалить.

Пересборка EXE не меняет схему и данные Oracle. Изменения внешних SQL-файлов попадут
во встроенный установщик только после пересборки, но к существующей базе сами не применятся.

## 11. Настройки и устранение неполадок

Параметры подключения сохраняются в `%APPDATA%\OracleQuizPlatform\connection.json`.
Пароль схемы в этот файл не записывается. Журналы установки находятся в
`%APPDATA%\OracleQuizPlatform\install_logs\`.

| Проблема | Что проверить |
| --- | --- |
| Нет подключения к Oracle | Сервер, порт, доступность сети, SID или имя службы |
| `ORA-01017` | Имя и пароль пользователя схемы; это не логин и пароль аккаунта приложения |
| `ORA-01031` или ошибка квоты | Необходимые права и свободную квоту у администратора базы |
| `SP2-0310` | Наличие всей папки `sql` и пути к вложенным файлам; можно использовать установку из EXE |
| `ORA-20998` | Не создан обязательный объект; изучите предыдущие ошибки установки |
| `ORA-20999` или ошибки компиляции | Вывод `check_installation.sql` и причины невалидных объектов |
| Некорректно отображается русский текст из базы | Кодировку UTF-8 SQL-файлов и правильность ранее загруженных данных |
| Не удаётся заменить EXE | Закрыто ли приложение и есть ли права записи в папку |
| Не запускается EXE | Windows x64, сообщения защиты Windows и самопроверку приложения |

Для самопроверки EXE выполните из релизной папки:

```powershell
$exe = Join-Path $PWD 'OracleQuizPlatform.exe'
$report = Join-Path $env:TEMP 'OracleQuizPlatform-check.json'
$p = Start-Process -FilePath $exe -ArgumentList @('--self-check', ('"{0}"' -f $report)) -WindowStyle Hidden -Wait -PassThru
$p.ExitCode
Get-Content -LiteralPath $report
```

Ожидаются код `0` и `ok: true`. Проверка не меняет данные и не подключается к Oracle;
доступность сервера и реквизиты подключения проверяются отдельно.
При обращении за помощью передавайте текст ошибки и журнал, но не пароли.

## 12. Загрузка комплекта в GitLab

Для запуска двойным щелчком используйте **`upload_gitlab.cmd`**, а не PS1-файл.
Оба файла должны находиться в корне релизной папки рядом с EXE и README.
Окно CMD остаётся открытым после завершения или ошибки. Прочитайте итоговое сообщение
и только затем нажмите любую клавишу для закрытия. Этот способ уже передаёт `-AllowHttp`
для указанного учебного сервера; предупреждение о нешифрованной передаче остаётся.

Скрипт `publish_gitlab.ps1` загружает файлы этой папки прямо в корень проекта,
без дополнительной подпапки, включая EXE и исходники. Существующий `README.md`
заменяется этой инструкцией. Остальные совпадающие файлы обновляются, а файлы,
которых нет в комплекте, из репозитория не удаляются. История прежних коммитов сохраняется.
Переноса истории разработки из другого репозитория не происходит.

Указанный по умолчанию адрес:

```text
http://10.22.10.16/25-26-spring/discipline-pvsbd/group-ks-23-18/group-ks-23-18-pvsbd-kalinin_syu.git
```

Нужны Windows PowerShell 5.1 или новее, доступ к этому серверу и токен GitLab
с областью действия `api`. У владельца токена должно быть право записи в ветку `main`.
В настройках своего профиля GitLab откройте Access Tokens, создайте токен с коротким
сроком действия и областью `api`. Названия пунктов могут отличаться в разных версиях.
Не записывайте токен в файлы проекта и не передавайте его другим людям.

1. Откройте PowerShell в релизной папке.
2. При желании проверьте список файлов без подключения к серверу:

```powershell
powershell -ExecutionPolicy Bypass -File .\publish_gitlab.ps1 -DryRun
```

3. Для загрузки на указанный учебный сервер выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\publish_gitlab.ps1 -AllowHttp
```

4. Проверьте адрес, ветку и список файлов, затем введите `UPLOAD` для подтверждения.
5. Введите токен в скрытом поле ввода. Его символы не отображаются.
6. Дождитесь сообщения `Upload verified` и откройте показанную ссылку на коммит.

**HTTP не шифрует токен и передаваемые файлы.** Параметр `-AllowHttp` явно разрешает
такую передачу. Используйте его только в доверенной учебной сети; после загрузки
отзовите токен. Если администратор предоставляет HTTPS, укажите HTTPS-адрес через
параметр `-RepositoryUrl` и не используйте `-AllowHttp`. Проверка сертификатов не отключается.

Скрипт не требует Git или Python, не устанавливает схему Oracle и не запускает EXE.
Служебные файлы окружений, кэши, архивы и файлы с типичными именами секретов исключаются.
Это не проверка содержимого на наличие паролей: перед отправкой просмотрите комплект.
Все изменённые файлы передаются одним коммитом; содержимое проверяется по контрольным
суммам. Если файлы уже совпадают, новый коммит не создаётся. В сообщении коммита
используется `[skip ci]`, чтобы не запускать обычную сборку GitLab при загрузке комплекта.

При `403` проверьте права и защиту ветки у владельца проекта. При `413` сервер
ограничивает размер запроса: обратитесь к администратору GitLab, файлы молча не пропускаются.
Если соединение оборвалось во время отправки, сначала проверьте коммиты на сервере:
загрузка могла завершиться. Скрипт не повторяет отправку автоматически.

Если окно ранее сразу закрывалось, откройте PowerShell вручную в релизной папке
и выполните приведённую выше команду с `-AllowHttp`. При ошибке передайте её текст
или снимок экрана, но не токен. Сообщение `Missing` означает, что выбрана не вся
релизная папка; сообщение о HTTP означает отсутствие параметра `-AllowHttp`.
