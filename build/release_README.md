# Oracle Quiz Platform: установка и использование

Релиз подготовлен {{DATE}}. Версия исходников приложения: `{{COMMIT}}`.
В этой папке находится готовое приложение для Windows x64, исходный код и SQL для
установки в Oracle. База данных находится отдельно: копирование папки не переносит
уже существующие аккаунты, тесты и результаты из другой базы.

## 1. Состав папки

```text
OracleQuizPlatform_Release/
  OracleQuizPlatform.exe       готовое приложение
  README.md                    эта инструкция
  requirements.txt             зависимости для запуска Python-исходников
  app/
    quiz_app.py                запуск из исходников
    quiz_client/               интерфейс, связь с Oracle, установщик
  sql/
    install.sql                установка С УДАЛЕНИЕМ старых данных проекта
    00_uninstall.sql           внутренний этап переустановки, отдельно не запускать
    check_installation.sql     проверка компиляции объектов, не создаёт тестовые данные
    upgrade_quiz_invitations.sql  обновление актуальной установленной базы
    upgrade_quiz_access.sql    зависимость обновления приглашений
    upgrade_no_views.sql       обновление более ранней версии с представлениями
    upgrade_question_selection.sql  зависимость полного обновления
    01_tables/                таблицы и индексы
    02_functions/             SQL-функции
    03_procedures/            регистрация и вход
    04_triggers/              проверки и автоматические действия
    05_packages/              бизнес-логика и отчёты
    07_seed/                  начальные аккаунты, тесты и результаты
    08_migrations/            миграция подбора, необходимая для обновления
```

Тестовые сценарии, Docker, виртуальное окружение, кэши, временные файлы сборки,
настройки вашей машины и прочие MD-файлы не включены. Проверка `check_installation.sql`
не является демонстрационным тестом: она нужна для обнаружения ошибок компиляции.
SQL-файлы также встроены в EXE, без тестовых сценариев. Python, SQL Developer и
Oracle Client не требуются для запуска готового EXE и встроенной установки.

Переносите всю папку целиком, например в `C:\OracleQuizPlatform_Release`.
Желательно использовать короткий путь без кириллицы для ручного запуска SQL-скриптов.
Для просмотра кода преподавателю используйте `app` и `sql`; для запуска достаточно EXE
и доступной Oracle. Административный запуск EXE не требуется.

## 2. Что должно быть подготовлено на сервере Oracle

SQL Developer является клиентом, не самой базой. Oracle должна быть уже установлена,
запущена и доступна по сети. Пользователь схемы Oracle должен существовать заранее.
Приложение не устанавливает Oracle, не создаёт её пользователей и не выдаёт им права.

У администратора БД нужно узнать:

- адрес сервера и порт;
- SID либо имя службы (это разные параметры);
- имя пользователя схемы и его пароль;
- наличие прав CREATE SESSION, CREATE TABLE, CREATE SEQUENCE, CREATE PROCEDURE,
  CREATE TRIGGER и свободной квоты на табличное пространство по умолчанию.

Для демонстрационного набора выделялась квота 300 МБ. CREATE VIEW, SYS и DBA не нужны.
Используйте свою выделенную схему, не SYS/SYSTEM/PDBADMIN. На сервере должны быть
доступны обычные встроенные возможности Oracle, используемые пакетами проекта.

Проверка сети в PowerShell (подставьте адрес вашего сервера):

```powershell
Test-NetConnection 10.22.10.64 -Port 1521
```

При наличии SQL Developer можно проверить схему и права:

```sql
SELECT USER FROM dual;
SELECT privilege FROM session_privs ORDER BY privilege;
SELECT default_tablespace FROM user_users;
SELECT tablespace_name, bytes, max_bytes FROM user_ts_quotas;
```

Квота 300 МБ отображается как `314572800`, неограниченная как `-1`.
Эти проверки ничего не изменяют. Недостающие права и квоту выдаёт администратор Oracle.

## 3. Подключение

Запустите `OracleQuizPlatform.exe` и заполните поля:

| Поле | Пример учебного подключения |
| --- | --- |
| Сервер | `10.22.10.64` |
| Порт | `1521` |
| Тип подключения | `SID` |
| SID | `orcl` |
| Пользователь схемы | `KA2105_01` |
| Пароль схемы | Пароль, выданный для этой схемы |

Это пример ранее использовавшегося подключения, а не универсальные реквизиты.
Сверяйте значения с рабочим подключением SQL Developer. Если администратор выдал
Service name, выберите «Имя службы», а не SID. Для сложной конфигурации оставлен
дополнительный режим ввода готового DSN.

Пользователь схемы Oracle и пользователь приложения различаются: сначала подключение
к схеме, затем вход в приложение под `admin`, `author`, `student` или своим логином.

## 4. Новая установка через приложение

**ВНИМАНИЕ: установка удаляет существующие данные проекта в выбранной схеме:
аккаунты приложения, тесты, ответы, попытки и результаты. Это не обновление.**

1. Убедитесь, что нужна именно новая установка и в схеме нет данных проекта для сохранения.
2. Заполните реквизиты схемы на первом экране.
3. Нажмите «Установить базу приложения (install.sql)».
4. Подтвердите предупреждение и повторно введите имя схемы.
5. Дождитесь успешного завершения в окне прогресса.
6. Закройте окно установки и нажмите «Подключиться».
7. Войдите под одним из начальных аккаунтов, приведённых ниже.

Установщик проверяет комплект SQL, права и свободную квоту до удаления объектов.
Не выключайте приложение и не разрывайте сеть во время установки. На время операции
другие клиенты должны быть отключены от этой схемы. Ошибка останавливает исполнение
с указанием файла и строки; уже выполненные CREATE/DROP не откатываются полностью.
Повторять установку после устранения ошибки можно только при допустимости удаления
данных этой схемы. Пароль самой схемы Oracle не меняется.

Если база уже установлена, для каждого следующего запуска нужна только кнопка
«Подключиться». На нескольких компьютерах, использующих одну схему, установка
выполняется один раз, а не отдельно на каждом компьютере.

## 5. Альтернатива: установка через SQL Developer

Выполняется вместо встроенной установки, не после неё:

1. В SQL Developer выберите свою схему, роль Default, без SYS.
2. В Tools → Preferences → Environment установите Encoding = UTF-8.
3. После смены кодировки закройте и заново откройте SQL-файл.
4. Через File → Open откройте именно `sql/install.sql` из этой папки.
5. Выберите нужное подключение и нажмите F5 (Run Script), не Ctrl+Enter.
6. Дождитесь сообщения `Quiz platform installed successfully` и отсутствия ORA-/SP2-ошибок.
7. При необходимости выполните `sql/check_installation.sql` через F5: ожидается
   `All Oracle objects are VALID`, без строк ошибок компиляции.
8. Запустите EXE, подключитесь и войдите в приложение.

Не копируйте текст install.sql в отдельную пустую вкладку: пути `@@` должны разрешаться
относительно исходного файла. Не переносите install.sql отдельно от папок sql.
Если файлы не открываются, проверьте целостность папки и открытие скрипта через File → Open.
Если русский текст в самом SQL отображается неверно, не запускайте его: проверьте UTF-8.
Исправление кодировки не исправляет уже испорченные строки в БД автоматически.

## 6. Обновление существующей базы БЕЗ удаления данных

**Не нажимайте «Установить базу приложения» и не запускайте install.sql.**

1. Сделайте резервную копию средствами, согласованными с администратором БД.
2. Закройте клиенты приложения, подключённые к обновляемой схеме.
3. Перенесите эту папку целиком. Откройте в SQL Developer скрипт обновления с UTF-8.
4. Для актуальной версии, где уже есть режимы таймера, лимит попыток, подбор и
   pkg_reports, выполните `sql/upgrade_quiz_invitations.sql` через F5.
5. Для более ранней версии с представлениями выполните `sql/upgrade_no_views.sql`.
   Он рассчитан на базу, где уже есть режимы таймера и лимит попыток; добавляет поля
   подбора и обновляет серверные модули, включая приглашения и отчёты без CREATE VIEW.
6. Проверьте `sql/check_installation.sql`, затем используйте новый EXE.

Не выполняйте оба скрипта подряд без необходимости: выбирайте подходящий вариант.
Для произвольной очень старой схемы автоматическая совместимость не гарантирована:
сначала сравните её структуру с этой версией, не применяйте переустановку ради исправления.
Обновление сохраняет данные и пароли; начальные аккаунты и демонстрационные результаты
повторно не добавляются. Скрипты обновления не требуют CREATE VIEW.

## 7. Начальные аккаунты и данные

Только после чистой установки:

| Логин | Пароль | Роль |
| --- | --- | --- |
| `admin` | `Admin123!` | Администратор |
| `author` | `Author123!` | Автор |
| `student` | `Student123!` | Участник |

После обновления используйте ваши прежние пароли, а не обязательно эти значения.
Начальные пароли демонстрационные; перед рабочим использованием их следует сменить
через административные функции. При переустановке прежние пароли приложения теряются.

Создаются три теста: Oracle, математика, русский язык. В каждом шесть вопросов разных
типов. Сохранены 24 демонстрационные попытки и 144 ответа: у author и student по
12 прохождений. Эти данные нужны для демонстрации, это не файлы автоматических тестов.

## 8. Работа с приложением

- Участник: зарегистрироваться или войти, выбрать тест в каталоге, пройти его,
  открыть результат и историю. Лимит попыток и таймер проверяются в Oracle.
- Автор: открыть «Студию тестов», создать тематику/категорию и тест, добавить вопросы,
  настроить подбор, таймер, лимит попыток и показ пояснений, затем опубликовать.
- Поддерживаются один вариант, несколько вариантов, текст, число, верно/неверно,
  последовательность. У одиночного выбора один правильный вариант, у множественного
  не менее двух. Последовательности можно переставлять мышью.
- Подбор N вопросов выполняется из вопросов выбранного теста по категории и сложности.
- Настройки опубликованного теста редактируются после возврата в черновик.
- Во вкладке «Публикация» выберите тест: там меняется публичный/закрытый доступ,
  показываются пользователи с доступом и дата приглашения. Выдача и отзыв относятся
  к выбранному тесту. После действия список обновляется без повторного входа.
- Отзыв приглашения запрещает новые попытки, но сохраняет результаты и начатую попытку.
  Автор и администратор имеют доступ по роли; этой кнопкой он не отзывается.
- Администратор дополнительно управляет авторами/пользователями: роли, смена пароля,
  отключение, удаление, сброс попыток. Удаление и сброс подтверждайте внимательно.
- Отчёты показывают баллы, процент, историю, сравнение со средним и статистику вопросов.
  Объяснения доступны участнику только при разрешении автора.
- При нехватке места используйте прокрутку, Tab и изменение размера окна.
  Enter выполняет основное действие на экране входа или прохождения.

## 9. Где настройки, журнал и данные

- Данные приложения хранятся в Oracle, не в папке EXE. Для переноса накопленных
  данных между серверами нужен отдельный экспорт/импорт БД, согласованный с администратором.
- `%APPDATA%\OracleQuizPlatform\connection.json`: адрес подключения и имя схемы;
  пароль схемы туда не записывается.
- `%APPDATA%\OracleQuizPlatform\install_logs\`: журналы встроенной установки.
  Пароль схемы маскируется; перед передачей журнала проверьте его содержимое.
- SQL внутри EXE соответствует этой версии. Редактирование внешних sql-файлов
  не меняет встроенный установщик: для новых скриптов нужна новая сборка EXE.

## 10. Диагностика

Из PowerShell, открытого в релизной папке:

```powershell
$exe = Join-Path $PWD 'OracleQuizPlatform.exe'
$report = Join-Path $env:TEMP 'OracleQuizPlatform-check.json'
$p = Start-Process -FilePath $exe -ArgumentList @('--self-check', ('"{0}"' -f $report)) -Wait -PassThru
$p.ExitCode
Get-Content -LiteralPath $report
```

Ожидается код 0 и `ok: true`. Проверяются драйвер Oracle, cryptography, Tkinter и
встроенный комплект SQL. Это диагностика, данные БД она не меняет и сеть не проверяет.

- Нет соединения: проверьте сервер, порт, сеть/VPN, SID/Service name и запуск Oracle.
- ORA-01017: неверные реквизиты схемы; это не пароль admin приложения.
- ORA-01031 или сообщение о квоте: обратитесь к администратору БД, не используйте SYS.
- Ошибки компиляции: выполните check_installation.sql и сохраните вывод; не игнорируйте их.
- После замены EXE нет новой процедуры: сначала выполните подходящее обновление БД.
- Кракозябры только в тестах: проверьте кодировку исходного SQL и сохранённые данные БД.
- Не запускается EXE: используйте Windows x64, проверьте сообщения защиты Windows
  и самопроверку. Не отключайте защиту глобально; при необходимости обратитесь к администратору.

## 11. Просмотр и запуск исходников

Для защиты проекта открывайте `.py` из app и SQL/PLSQL из sql. Python отвечает за
интерфейс, вызовы Oracle и установку. Расчёты, ограничения, доступ и данные выполняются
на сервере: pkg_admin, pkg_testing, pkg_reports, функции и триггеры.

Если нужен запуск без EXE, установите Python 3.12 x64 с Tkinter и в этой папке выполните:

```powershell
py -3.12 -m pip install -r requirements.txt
py -3.12 app/quiz_app.py
```

Для обычного запуска EXE эти команды не нужны. Средства сборки и автоматические тесты
не включены в релизную папку; они остаются в рабочем репозитории проекта.
